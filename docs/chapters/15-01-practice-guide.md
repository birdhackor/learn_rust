# 15.1 最終練功：自己完成一個可以使用的工具

第 7 章已把純工作、檔案、參數、JSON 與行程測試接成完整工具。最後一章把工作交回給你：先讀懂需求與材料，自己寫下一小段、驗收它，再接上下一階段。每題都會提供完整可用的參考版，卡住時能比較原因，完成後也能拿來使用。

兩題各以核心約一千行 Rust 為規模，另外提供驗收測試與本機測試材料；各題的完整答案會分別列出實際行數。這是控制負擔的目標，不要求你湊行數，也不要求一次手寫全部參考測試。只計一份完整版本，不把不同階段的相同程式累加。你可以每次只實作一題，完成一個里程碑再往前走。

## 兩個需要，兩條完整路線

**A：重複檔案搜尋器。** 備份與整理資料夾時，想知道哪些不同路徑保存完全相同的內容。給它一個根目錄，工具走訪其中的檔案，列出內容相同的群組；能輸出文字或 JSON，也說明哪些項目未能完成判定。

**B：網址檢查器。** 維護一份連結清單時，想分辨哪些可取得預期回應，哪些未通過、連不上、等待超時或被使用者中止。給它每行一個網址的文字檔，工具限制同時進行的工作數，最後依輸入順序交回結果。詳細的網路與中止政策在 B1 固定，再逐步實作。

B 的網址稱為 URL（Uniform Resource Locator，統一資源定位符），是指向網路資源的位置表示。這份清單若把同一個網址寫兩次，就是兩筆輸入，應各保存自己的行號與結果；不因網址相同就合併。這和 A 按不同檔案路徑整理內容，是兩種不同的資料身分需求。

兩題的練法相同：先固定需要回答什麼，再決定資料與 ownership 怎麼流動。第三方 library 提供已教的能力，哪些輸入接受、錯誤是否繼續、報告怎麼排序，仍由你的程式保存。

## 先用真實材料讀清楚 A 的答案

教材準備了一份小型資料夾，位於 `examples/ch15-projects/materials/duplicate-demo`。以下路徑以它為根目錄；它只包含這六個一般檔案與所需子目錄：

| 路徑 | 完整內容與長度 |
| --- | --- |
| `notes-a.txt` | Rust 後接一個 LF，5 bytes |
| `sub/notes-b.txt` | Rust 後接一個 LF，5 bytes |
| `.saved/notes-c.txt` | Rust 後接一個 LF，5 bytes |
| `different.txt` | rust 後接一個 LF，5 bytes |
| `empty-a.bin` | 空內容，0 bytes |
| `empty-b.bin` | 空內容，0 bytes |

第一份檔案實際內容如下，Rust 之後有行尾；長度沿用 7.3–7.4 的 byte 意義：

```text
--8<-- "examples/ch15-projects/materials/duplicate-demo/notes-a.txt"
```

預期有兩組：notes-a、sub/notes-b、.saved/notes-c 三個路徑同內容；empty-a 與 empty-b 也是同內容。different 與前三份同樣是 5 bytes，第一個字母的 byte 卻不同，所以不能加入那一組。**大小相同只是值得進一步檢查，尚未回答內容相同。**

`.saved` 名稱以點開頭，本題也要走進這類目錄。重複判定不限文字檔；這份材料採容易直接核對的文字與空內容，後面的檢查還會加入一般 bytes、跨 buffer 與失敗情況。

每組的「重複內容 bytes」按 `(路徑數 − 1) × 檔案長度` 計算：第一組是 `(3 − 1) × 5 = 10`，空檔組是 0，合計 10。它描述依路徑計算的重複內容，不保證移除一個路徑就能釋出同樣多的實體磁碟空間。完整工具只產生報告；這份練習沒有刪除功能。

### A 的完成範圍

A 的根目錄可以包含一般檔案與子目錄，包括上述點開頭的名字。**symbolic link（符號連結）** 是檔案系統中指向另一個位置的入口；本工具不跟隨它，也不接受根路徑本身是這種入口，具體判定在 A1 教學中實作。

核心保留原生 PathBuf，完成版處理能表示為 Unicode 的路徑。遇到不能處理的項目，保存可辨認的診斷並跳過，繼續其他項目；不把 path.display 的可能失真文字當身分。

檔案在掃描期間可能改變。完成版保留讀取前後可觀察的變動與讀取問題，標示判定不完整；沒有宣稱凍結整個檔案系統或保證絕不漏掉同時發生的變化。

本題狀態也有自己的契約，不能只套用某個舊工具的數字：0 是完整完成，包含沒有重複；1 是有項目失敗、結果不完整；2 是根設定、輸入或報告輸出等致命錯誤。資料、診斷與狀態的分工沿用 7.5／7.9。

## 工作版、完成快照與完整參考版

每階段會提供三種不同用途的入口：

- **工作版／起始檔：** 告訴你要修改的檔案、介面與待完成範圍，留給你自行實作。能編譯不代表功能完成；相應測試若仍應失敗，會標明原因。
- **本階段完成快照：** 只包含截至這一步的成果，方便比對自己卡在哪裡，不會悄悄放入後面才用的 API。
- **完整參考版：** 保存相同需求下的全部功能、限制、建置與使用方法，A 在 15.6，B 在 15.11。你可以按需要查看；它也是可以實際使用的答案。

先保留自己的工作版，再對照一小段。若看到答案能執行，還要問：它取得哪份資料的 ownership？失敗從哪裡交回？哪個 assertion 保存了我們剛定的規則？這樣才能把差異用回自己的版本。

### 建立自己的練習位置

在教材 repo 之外，選一個自有練習資料夾並開啟終端機，讓自己的 Cargo.toml、Cargo.lock 與實作進度各自管理。先沿用 1.2 的 Cargo new 建立 A 的工作位置。

教材 repo 的 rust-toolchain.toml 選定 Rust 1.99.0，這份選擇不會自動套到 repo 外的新資料夾。這裡使用 **`cargo +1.99.0`**：由 rustup 為這次命令選取已安裝的 1.99.0 toolchain；`+1.99.0` 放在 Cargo 子命令前，不是 dependency 的版本要求，也不修改全機預設。後面的練習命令同樣保留這份選擇：

```bash
cargo +1.99.0 new duplicate-finder
cd duplicate-finder
cargo +1.99.0 check
cargo +1.99.0 test --locked
```

這時還是 Cargo 產生的起點。check 確認它能編譯；test 可能顯示零項，因為你還沒加入行為測試。 **零項通過沒有證明它已會掃描或判定重複。** 下一節會給 A1 所需的 manifest 設定、起始檔與資料介面，再從這裡加入功能。

之後先在自己的程式中使用 `cargo +1.99.0 check`、`cargo +1.99.0 test --locked`，再用 1.10 已教的 fmt／Clippy 檢查，也在子命令前選同一份 toolchain。新增依賴時按 7.1 先更新設定與解析版本，接著以 lock 保存；不要在 lock 尚未更新時把 --locked 的拒絕當成程式行為失敗。完成的 repo 快照命令則會明示 package 與目錄，沿用 9.1 的 workspace 選擇。

## 每次只完成一個能判斷的里程碑

| A 的階段 | 結束時應能看到什麼 |
| --- | --- |
| A1，15.2：收集 | 納入哪些檔案、哪些項目有問題；此時還沒有宣稱找到重複 |
| A2，15.3：判定 | 真正內容相同的群組，同大小不同內容已分開，空檔也可成組 |
| A3，15.4：報告 | 穩定排序、10 bytes 等指標的意義、文字／JSON 與不完整資訊 |
| A4，15.5：CLI | 真正接收根目錄、交出資料／診斷與 0／1／2，完整 fixture 驗收 |
| 15.6：完整版 | 可建置、執行與測試的工具，並能查其限制與設計理由 |

B 也從一筆網址開始，再依序批次，接著加入有上限的同時工作，最後處理中止、排序與報告。這讓每次改動仍有固定的輸入與答案，不靠一口氣完成整個工具猜錯誤在哪裡。

每節先給本階段需要與材料。接著請你寫下預期結果，動手實作並跑對應測試；必要時才打開提示：第一層幫你辨認資料流，第二層提醒已教的能力，第三層給局部結構。完整答案另有入口，提示不會代替你完成整段工作。

例如 A1 還只交出收集資料，就先確認上述六個檔案都被納入；不要拿「重複組數仍為零」判它失敗。進到 A2，才把 notes-a／notes-b／notes-c 應同組、different 應分開，作為新階段必須完成的判準。

新增失敗情況時，像 7.8 的 fixture 與 7.9 的可控制 writer 一樣，讓材料確定產生你要檢查的原因。檢查失敗是否保留、其他可讀項目能否繼續，不以某台機器剛好沒有權限或公共網站剛好離線作固定答案。一次通過也只支持已測的規則，繼續核對本階段列出的其他行為。

## 開寫前先自己說出答案

先不寫 A 的核心程式，回答這三項：為什麼 different 不能和 notes-a 同組？兩個空檔能否同組？如果某項目判定失敗，仍交出其他群組時，結果可以說完整嗎？

??? note "核對自己的判斷"

    different 只有大小相同，內容 bytes 不同；兩個空檔的全部內容相同，可以同組；有項目未完成就要保留問題並標示不完整，不能因已找到幾組就宣稱全部判定成功。

現在已有一份能核對的材料、明確的完成範圍與自己的工作位置。下一節先完成 A1：收集檔案與項目問題，讓後面的內容判定拿到正確資料。
