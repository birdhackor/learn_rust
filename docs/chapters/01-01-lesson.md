# 1.1 從 Python 出發，準備 Rust 環境

如果你已經能用 Python 寫變數、函式、條件與迴圈，就有足夠的背景開始這份教材。你不需要先學 C 或 C++。我們會先做一個小型數字運算程式，接著把重複的計算寫成函式，並認識執行時使用的記憶體。讀完第一章，你會知道一份 Rust 程式如何從文字變成能執行的工具。

Python 讓你很快把想法寫成程式；當程式開始管理較多資料、重複使用同一份資料，或同時執行幾項工作時，另一個問題會變得重要：哪些錯誤能在程式真正開始工作前被發現？Rust 把許多檢查放在**編譯**階段。編譯器閱讀原始碼、檢查它是否符合語言規則，再產生電腦能執行的程式。檢查通過不代表計算邏輯一定正確，因此還要比對實際輸出與預期答案；第 2 章再學如何把這些比對寫成測試。

後面的閱讀路線會從資料如何表示、由誰管理、哪些操作允許共用資料，走到檔案工具、同時執行的工作與完整實戰。現在先把編寫、檢查、執行這個循環建立起來；每一步需要的新概念都會先解釋，再放進程式。

## 三個工具各做什麼

安裝 Rust 時，你會得到幾個常一起出現的名稱。它們不是三種不同語言：

| 工具 | 在工作流程中的角色 |
| --- | --- |
| `rustup` | 安裝與選擇 Rust 工具的版本。它讓同一台電腦可以使用不同版本的工具鏈；工具鏈就是一起使用的編譯器與相關工具。 |
| `rustc` | Rust 編譯器，負責讀取 Rust 原始碼並檢查、編譯。 |
| `cargo` | 管理專案與建置工作：建立資料夾、呼叫編譯器、執行程式及測試。後面需要別人提供的程式庫時，也由它管理。 |

平常我們會下 `cargo` 指令，由 Cargo 決定如何呼叫 `rustc`。`rustup` 則是在安裝、選版本時使用。編譯完成後的可執行檔是另一份檔案；它不是你正在編輯的 `.rs` 原始碼。

## 安裝並確認可以呼叫工具

本書指令寫在標示為 `bash` 或 `text` 的區塊中。它們應在**終端機**輸入，也就是接受指令的視窗；不要貼進 Rust 原始碼。區塊沒有開頭的 `$` 提示符，整行可以直接複製。`cd` 代表切換目前工作的資料夾；後續操作會以那個資料夾為起點。

### Linux 或 macOS

先開啟終端機。以下指令從 Rust 官方網站下載安裝程式，再交給 `sh` 執行；`|` 把左邊下載到的內容送給右邊：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

安裝畫面一般可選預設的 stable 工具鏈。stable 是 Rust 正式發布的穩定版本系列。完成後重新開啟終端機，讓新安裝的指令位置生效。

Rust 產生可執行檔還需要 linker：它把編譯後的部分及所需的系統程式連接成最後的檔案。這是建置工具的工作，現在不需要懂 C 語言。

macOS 若還沒有開發工具，`xcode-select` 是管理 Apple 開發工具位置的指令，`--install` 請求安裝命令列開發工具：

```bash
xcode-select --install
```

Ubuntu／Debian 使用 `apt` 這個系統套件管理工具。`apt update` 更新可安裝套件的清單，`apt install build-essential` 安裝包含編譯與連接工具的一組套件。前面的 `sudo` 以管理者權限執行這項工作，可能要求你的登入密碼；在詢問是否繼續時確認安裝即可：

```bash
sudo apt update
sudo apt install build-essential
```

其他 Linux 發行版使用各自的套件管理工具，依該系統的開發工具安裝方式處理。若已經具備這些工具，無須重複安裝。

### Windows

到 [Rust 官方安裝頁](https://www.rust-lang.org/tools/install)下載並執行 `rustup-init.exe`。依安裝程式提示安裝 Visual Studio 的 C++ 建置工具；這提供 linker 與系統程式庫，不表示你必須先學 C++。完成後重新開啟 PowerShell，接著使用下列相同的版本檢查指令。

### 版本檢查

`--version` 的意思是「顯示版本」，不是編譯程式。現在依序確認三個工具都能呼叫：

```bash
rustup --version
rustc --version
cargo --version
```

每行都應印出工具名稱及版本。如果顯示 `command not found` 或找不到指令，先重新開啟終端機；若仍找不到，檢查安裝是否完成，以及系統是否已把 Rust 的指令資料夾加入搜尋位置。

本教材的程式採用 Rust **edition 2024**，並以 Rust **1.99.0** 驗證。edition 是一組語言規則的版本，與工具的發布版本不同；下一節會在專案設定中看到它。教材 repo 會固定工具版本，讓範例的檢查結果容易重現。自行建立練習專案時，安裝近期 stable 即可；若要完整重現 repo，請保留 repo 的 `rust-toolchain.toml`。

## 編輯器與這一章的第一個目標

任何能保存純文字的編輯器都可以寫 `.rs` 檔案。若使用 Visual Studio Code，可安裝 `rust-analyzer` 擴充套件；它會在編輯時提供檢查與提示。終端機中的 Cargo 指令仍然是這份教材共同使用的操作方式，因此不論用哪個編輯器，你都能依同一個步驟驗證程式。

先確認你能回答：安裝版本由哪個工具負責？真正檢查 Rust 原始碼的是誰？平常建立和執行專案會呼叫誰？答案依序是 `rustup`、`rustc`、`cargo`。下一節會用 Cargo 建立一個只印出一行文字的程式，親眼分辨「檢查通過」與「真的執行」。


## 練習與完整答案

不用安裝任何新東西，先在終端機查出編譯器與 Cargo 的版本，再用一句話說出兩者的分工。

參考操作如下；實際的版本號依你所在的專案與安裝狀態而定：

```bash
rustc --version
cargo --version
```

`rustc` 讀取並檢查 Rust 原始碼、產生編譯成果；Cargo 根據專案設定安排建置，再呼叫 `rustc`。若第一行找不到指令，先完成上面的安裝檢查，還沒到修改程式的階段。
