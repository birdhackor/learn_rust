# 7.6 clap：讓參數規則產生 owned 設定

7.5 的工具只接受一個檔名，手寫 next 已足以完成它。接下來要為文字搜尋準備兩個必要資料：要找的文字、要讀的檔名；呼叫者還可以要求忽略大小寫，並查詢用法與版本。

這些規則可以繼續手寫，但需要自己維護位置、開關與說明之間的對應。**clap** 是 command-line argument parser（命令列參數解析 library），這次讓它依 struct 欄位建立規則、產生說明，再交回 owned 設定。搜尋行為留到 7.9；本節只驗收參數如何成為設定，以及顯示請求如何交給呼叫者。

本節使用 `ch07-clap` package。從 repo 根目錄執行 `cd examples/ch07-cli/clap`，以下指令在此執行。

## 先決定輸入與設定的對應

先讀呼叫方式。下面是預期交給程式的三筆參數，程式名稱之外還有兩項必要資料與一個開關：

```text
query-settings Rust 中文筆記.txt --ignore-case
```

| 輸入 | 角色 | 成功設定 |
| --- | --- | --- |
| `Rust` | 第一個 positional（位置參數），以順序決定角色 | `query: String`，擁有要找的文字 |
| `中文筆記.txt` | 第二個 positional，指定檔名 | `filename: PathBuf`，擁有原生路徑 |
| `--ignore-case` | flag（開關），用名稱選擇是否啟用，不再跟一個值 | `ignore_case: bool`，有它為 true，省略為 false |

query 是文字，必須能成為 UTF-8 String；filename 保存 PathBuf，可保留原生檔名。clap 解析 filename 不會替我們開檔案或保證檔案存在，仍保留 7.5「路徑表示與真正 I/O 分開」的關係。

開關使用兩個連字號的 long 名稱。本次只接受宣告過的名稱；拼成 `--unknown` 應是用法錯誤。ignore-case 在此只保存選擇，尚未執行任何大小寫轉換或搜尋。

## 用 derive 讓欄位提供 Parser 能力

沿用 7.1 的依賴與 feature 契約，選用 clap 的 derive feature。版本要求仍是範圍，實際解析版本由 Cargo.lock 保存：

```toml
--8<-- "examples/ch07-cli/clap/Cargo.toml:dependencies"
```

**`clap::Parser`** 是將命令列資料解析成設定型別的 trait。**`#[derive(Parser)]`** 依欄位和 attributes 生成相關實作；4.2 已教的 derive 仍是編譯時工作，並不是啟動程式時先執行某個 Parser 函式。

先把本次使用的 attributes 讀清楚：

- **`#[command(name = "...", version = "...", about = "...")]`** 設定工具的顯示名稱（例如版本輸出）、版本與用途；version 同時提供 `--version` 顯示請求。用法中的啟動名稱可取自 arguments 第一筆，所以本教材的 Cargo run 會顯示 ch07-clap。這些設定字串不是用來尋找執行檔。
- 欄位若沒有 short／long 設定，本次的 String／PathBuf 就是必要 positional，依宣告順序接受 query、filename。
- **`#[arg(long)]`** 在 bool 欄位上建立 long 開關；欄位 `ignore_case` 對應命令列的 `--ignore-case`。沒有輸入時為 false，有輸入時為 true。
- **`help = "..."`** 可放在 arg attribute，將欄位用途放入說明。clap 也提供 `--help`，呼叫者不用先給兩個必要 positional 就能查看用法。

它們是給 derive 的設定。生成的 parser 使用這些設定決定接受什麼；我們的程式使用成功回傳的欄位決定要做什麼。先保留 Debug，方便檢查意外得到的設定：

```rust
--8<-- "examples/ch07-cli/clap/src/lib.rs:settings"
```

## try_parse_from：先留下解析結果

這次選用 **`Settings::try_parse_from(input)`**，回傳 `Result<Settings, clap::Error>`。先引入 `use clap::Parser;`，才在型別上呼叫這個 trait 提供的方法。

input 必須是 `IntoIterator<Item = T>`，元素 T 要有 `Into<OsString> + Clone`：每筆能交成原生字串，並能依 Clone 的契約建立副本。7.5 已教 OsString 的 Clone；它也能以 Into 交回相同型別，因此 owned OsString array 與 args_os 都符合。這裡的第一筆仍是程式名稱，**把完整序列交給 clap，不自行先 next 略過**。

**`clap::Error`** 保存沒有產生 Settings 的結果，提供 Debug／Display。但 **Err 不全是使用者輸入錯誤**：`--help`、`--version` 需要顯示資訊並正常完成，同樣透過這個型別交回。

先選兩個 shared 借用方法辨認它們：

| 方法 | 結果與意義 |
| --- | --- |
| `error.use_stderr()` | bool；true 表示訊息該進 stderr，false 表示進 stdout |
| `error.exit_code()` | i32；此版本對 stderr 訊息回 2，對 stdout 顯示請求回 0 |

因此缺必要資料／未知開關的預期是 stderr、2；help／version 的預期是 stdout、0。try_parse_from 本身只交回結果，這一步不印訊息或結束行程。

下面先在 library 內測試。兩個成功情況分別核對開關省略與啟用；失敗保存用法判別；顯示請求則驗收正常結果。測試不依說明文字的整份排版，也不直接比較 clap::Error：

```rust
--8<-- "examples/ch07-cli/clap/src/lib.rs:settings-tests"
```

執行 `cargo test -p ch07-clap --locked`，共四項。這一步證明參數規則符合我們的設定介面；還沒證明真實 CLI 訊息寫到正確出口。

## 接上真正的 arguments、輸出與狀態

現在將 args_os 的完整序列交給相同方法，成功就以 7.5 的 Stdout／Write 顯示三個設定。這份程式是設定檢查工具，所以輸出欄位標示；不是已完成的文字搜尋結果。

Err 分支選用 **`error.print()`**：shared 借用 Error，依其訊息角色寫到 stdout 或 stderr，回傳 `io::Result<()>`。它只負責顯示，不會自行終止行程；顯示自身也可能遇到 I/O 失敗。caller 保留前一步的 exit_code，印成功才交回對應的 0 或 2；印失敗則交回標準 FAILURE。

有些範例使用 `Parser::parse` 或 `error.exit()` 直接結束行程。本節選 try_parse_from 加正常返回的 ExitCode，讓 library 可測試、呼叫邊界清楚，也保留 7.5 已教的 scope 清理。

```rust
--8<-- "examples/ch07-cli/clap/src/main.rs"
```

Cargo 的第一個 `--` 仍把其後資料交給程式；`--ignore-case` 才是程式的開關：

```bash
cargo run --quiet -p ch07-clap --locked -- Rust 中文筆記.txt --ignore-case
```

得到 query=Rust、filename=中文筆記.txt、ignore_case=true。省略開關就得到 false。檔案不用存在，因為這次還沒有讀取。

```bash
cargo run --quiet -p ch07-clap --locked -- --help
cargo run --quiet -p ch07-clap --locked -- --version
```

help 的 stdout 列出兩個必要位置參數與已宣告開關，version 顯示 query-settings 0.1.0；兩者結束狀態為 0。沿用 7.5 的分流保存與緊接 `echo $?`，少一個位置參數或改用 `--unknown` 時，可觀察 stdout 空白、stderr 有用法訊息、狀態為 2。

這裡解析成 Settings、回傳顯示請求／用法錯誤、真正寫出訊息，是三件不同的工作。讓它們分開，純參數測試就能先保存規則，main 再處理行程介面；7.8 會測真正的輸出與狀態。
