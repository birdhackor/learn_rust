# 1.8 重複工作，用迴圈累積答案

一份價目表有 120、80、200 三個數字，要把它們相加，現在可以逐項索引再相加。但當資料變多，每增加一項就要多寫一次操作。這一節要讓「取下一項、加進總額」成為重複的工作，直到材料用完。

## 已有一列材料，先用 for

**迴圈**讓同一段工作執行數次。`for price in prices { ... }` 會按照 array 的順序取得每一項數值，每次把該值命名為 `price`，執行一次 body。這裡使用具體的整數 array：每次拿到的是一個 `i32`，不是索引，因此可以直接相加。走到最後一項後就結束。

要保存跨次累積的答案，先在迴圈外建立 `let mut total = 0;`。每次做 `total += price;`，同一個 mutable 變數逐步改變；迴圈內的 `price` 則在每次處理的範圍內代表當次的值。處理 120 後為 120，接著加 80 變 200，最後加 200 變 400。

range 也可以放在 `for` 的 `in` 後面。`for number in 0..=3` 依序取得 0、1、2、3；上節已介紹兩端是否包含的區別。這不需要事先建立存放四個數字的 array。

## 不知道要做幾次，用條件控制

`while 條件 { ... }` 在每次執行 body **之前**檢查條件。條件為 `true` 就做一次，再回去檢查；一開始為 `false` 時一次也不做。例如計數從零開始，每次加一，當 `count < 3` 不成立就結束。必須讓某項工作有機會改變條件所依賴的資料，否則條件可能一直成立。

`loop { ... }` 則不自動檢查結束條件，每次做完 body 就回到開頭。`break;` 結束最近一層迴圈；在 `loop` 中也可以寫 `break 值;`，把那個值作為整個 `loop` expression 的結果。因此 `let found = loop { ... };` 能保存找到的數字。`break 值` 的所有離開路徑需要交出一致的型別。

若本次不需要繼續處理、但整個迴圈仍要進行，使用 `continue;`。它跳過 body 剩餘部分，進入下一次；`for` 會取下一項，`while` 會重新檢查條件。它和 `break` 的差別在於，前者只結束本次，後者結束整個最近迴圈。

## 把四種控制方式對照執行

下列完整程式先加總價格，再用 `while` 加總 1、2、3，用 `loop` 找到 3，最後用 `continue` 跳過 range 中的 2。原本 0、1、2、3 的總和是 6，跳過 2 後變成 4，能看見少做一次加法的結果。變數與運算都是前面已用過的材料，新增的是重複工作的控制方式：


```text
for的總和=400
while的總和=6
loop找到的值=3
跳過2的總和=4
```

第二個 `let mut sum = 0;` 是前面已教的 shadowing，為最後一項示範建立新的累積值；它不是繼續使用 `while` 得到的 6。

同樣的 1 到 3 加總也能用 `for` 寫，所以這份例子並不表示 `while` 能完成某種 `for` 絕對做不到的工作。選擇依照材料：已有 array 或整數 range 的每一項，`for` 直接表達「全部走訪」；工作是否繼續取決於變動條件，`while` 直接表達「條件成立就繼續」；需要在 body 的不同位置決定停止或交出結果，`loop` 配合 `break` 更直接。

## 練習：讓函式接收三個數字

寫 `sum_three(values: [i32; 3]) -> i32`。參數是整個固定長度 array，函式用 `for` 加總後回傳答案，`main` 再顯示結果。先用 `[120, 80, 200]` 驗證 400，再用 `[0, -5, 5]` 驗證 0。

用第二組資料不是增加另一項演算法，而是確認累積真的使用每個輸入值，沒有把正數總和硬寫在函式裡。型別 `[i32; 3]` 也明確表示本練習只接受三項；等學到 slice，才會把介面改成任意長度。
