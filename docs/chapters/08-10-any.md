# 8.10 用Any辨識並取回確切資料型別

8.5讓清單只依共同的amount能力處理不同型別。現在換一項需要：一個事件帶有id，也帶有呼叫端自定義的附加資料；轉交事件的程式只保存資料，真正處理的人想取回原本的i32、String，或自己定義的struct。

這份附加資料稱為 **payload**，也就是隨事件一起帶著、供後續處理的內容。已知種類可以用enum；若種類由呼叫端擴充，傳遞層不想每次增加variant，也沒有一項amount那樣的共同業務操作，就可以考慮辨識原型別後取回資料。**`Any`** 是標準函式庫為這種確切型別辨識提供的trait。

## Any要求型別符合 'static，不要求reference永遠有效

Any位於 `std::any`。它要求實作型別符合 `'static`；標準函式庫已為符合這項要求的型別提供實作，本節的數字、String與沒有borrow欄位的自訂struct都能直接使用，不要另外手寫一份Any impl。

這裡沿用8.4：String符合 `'static` 型別bound，仍可以在局部scope建立、使用、清理。把局部String借成 **`&dyn Any`** 時，reference仍只在原String有效期間使用。內部型別不依賴短命borrow，與這一次對它的borrow能維持多久，是不同的兩個問題。

反過來，保存局部String的 `as_str()` 結果，實際型別是依賴那份String的borrowed reference，不能因此符合Any的要求。後面用fixture直接觀察，先看能操作的介面。

## downcast比對原型別，不做數值或文字轉換

**downcast** 在本節表示：從dyn Any的共同視圖，嘗試取回某個**確切型別T**的資料。caller在編譯時指定要找的T，執行時檢查payload原來是否就是這個型別；不符合就回傳缺值或失敗，不把原值改造成T。

第一份程式只借用資料，使用以下標準helper。`::<T>` 沿3.3的turbofish指定型別：

| 操作 | 契約與結果 |
| --- | --- |
| `view.is::<T>()` | T須符合Any。回傳bool，確認內部確切型別是否就是T，不讀取或轉移owned內容。 |
| `view.downcast_ref::<T>()` | 回傳 `Option<&T>`。型別相同就借到原T，否則None；來源有效性依這次shared borrow。 |

Any trait提供型別辨識能力，標準庫另為dyn Any提供這些泛型helper；它們不是8.5所禁止放進trait object method表的泛型trait method。helper的T由caller選定，再使用辨識資訊檢查，沒有要求vtable保存任意T的業務method。

下面的amount是i32、count是usize，數值同樣為80。inspect只嘗試i32，最後再示範局部String借用：

```rust
--8<-- "examples/ch08-smart-pointers/examples/any_borrowed.rs"
```

```bash
cargo run -p ch08-smart-pointers --example any_borrowed --locked
```

```text

借回i32=80
```

數值相等沒有讓兩個Rust型別相同。對usize做 `downcast_ref::<i32>()` 得到None，不是「80放得進i32所以可以轉換」。成功回傳的reference仍借原值；amount、count與String都沒有因為檢查而被拿走。

Any也不能用來查「這個值有沒有實作任意trait」，或按文字欄位名找資料。取回String後能呼叫as_str，是因為現在有已知的String reference。若工作始終只需要共同amount，8.5的Charge介面就能直接表達需要，不必先猜每一種具體型別。

## 把payload交進事件，再借用修改

事件模型Event持有id與 **`Box<dyn Any>`** payload。和8.5一樣，Box接手具體資料，轉成共同的owned trait object handle；Any的 `'static` 要求仍成立，不是轉成dyn後就忘掉借用限制。

建構函式event的 `payload: impl Any` 是6.4的參數形式，由caller提供符合Any的具體型別；函式把它交進Box，不clone資料。Event只是傳遞這份payload，沒有要求框架預先知道所有自訂struct。

要修改已知型別的payload，增加 **`downcast_mut::<T>()`**：它需要mutable的dyn Any視圖，回傳 `Option<&mut T>`。成功時borrow原T供修改，失敗時None，沒有建立另一份T。這仍是2.4的獨占mutable借用，不是shared reference下任意修改。

add_to_number接收 `&mut Event`，用Box已有的 `&mut *` 借用內容；若原型別是i32就加extra、回傳true，其他型別不動、回傳false。

### 含短命borrow的資料不能用Any隱藏要求

下面故意把局部String借出的文字reference交進 `Box<dyn Any>`，會收到 `E0597`。外層Box是owned，不代表內部reference取得原文字的ownership：

```rust
--8<-- "examples/ch08-smart-pointers/fixtures/compile-fail/any_non_static_borrow.rs"
```

把object bound寫 `+ '_` 也不會取消Any本身的 `'static` 要求。若這項傳遞需要owned文字，就交進String；若資料本來必須借外部來源，就保留能描述該來源的具體型別或其他合適介面，不用Any把真實借用關係藏起來。

## owned downcast把Box交接，失敗時交回原資料

若接收者要取得ownership，使用 **`boxed.downcast::<T>()`**。它接手整份 `Box<dyn Any>`，回傳 **`Result<Box<T>, Box<dyn Any>>`**：

- 型別符合時，Ok保存已知T的owned Box，接收者可以使用或交出T。
- 型別不符時，Err保存原來的Box，內容仍在；接收者可以保留它或再試其他T。

這和downcast_ref的 `Option<&T>` 是不同責任。呼叫owned downcast後，原boxed名稱已經發生move，無論成功或失敗，都要從Result接手對應的owner。

下圖沿著真正的String例子：第一次請求i32得到Err，第二次對交回的原Box請求String才成功。箭頭表示handle與Result的交接，不是把文字轉成數字。

## TypeId辨識的是你實際查詢的那個型別

**`TypeId`** 位於std::any，是用來比較型別身分的值。`TypeId::of::<T>()` 取得符合 `'static` 的T之身分；`==` 比較兩個TypeId是否相同。它已提供PartialEq與Debug，所以也能沿4.2用assert_eq比較；內部表示不需由我們解碼，它不是事件id或資料值。

Any的 **`type_id(&self)`** 回傳receiver的TypeId；對dyn Any內容呼叫時，得到被隱藏的具體資料型別。下面的concrete_id則是泛型helper：由輸入 `&T` 決定T，對這個T查詢Any的type_id。

```rust
--8<-- "examples/ch08-smart-pointers/src/payloads.rs:type-id"
```

**Box本身也是一種型別。** `Box<dyn Any>` 也符合Any；直接寫 `boxed.type_id()` 會先使用Box自身的Any能力，得到Box的TypeId。若目標是內部payload，先用 `&*boxed` 借成 `&dyn Any`，再查它的type_id，才能得到內部i32的身分。

正常程式把兩種receiver明確並列；concrete_id(&boxed)讓T明確是 `Box<dyn Any>`，與直接查Box自身的能力相同：

```rust
--8<-- "examples/ch08-smart-pointers/examples/any_type_id.rs"
```

```bash
cargo run -p ch08-smart-pointers --example any_type_id --locked
```

```text
內部資料的TypeId是i32=true
把Box本身當T時得到Box的TypeId=true
```

若誤以為直接boxed.type_id就是i32，下面故意失敗的fixture可以編譯，執行時assert_eq失敗，訊息包含 `left == right`。它比較的是Box身分與i32身分，不是Rust忘記原型別。

```rust
--8<-- "examples/ch08-smart-pointers/fixtures/runtime-fail/any_box_type_id.rs"
```

實際處理payload時，多半直接用is／downcast helper即可。TypeId適合程式內比較確切型別，不要把它的內部值當成跨建置穩定的保存格式或對外編號；版本與編譯環境改變時，不依賴其表示保持相同。

## 練習：取回呼叫端自定義的資料

在自己的example定義ExtraInfo，保存count2，交給event建立id3的事件。owned downcast請求ExtraInfo，成功後把count加1，再從Box取回owned struct，確認count3。失敗分支要接手原payload，不能在move後繼續用原事件payload名稱。

完成後可對照 [完整參考程式](https://github.com/birdhackor/learn_rust/blob/main/examples/ch08-smart-pointers/examples/any_solution.rs)，或執行 `cargo run -p ch08-smart-pointers --example any_solution --locked`。

library測試另外檢查i32與同數值usize的差別、成功修改只作用於原i32，以及owned downcast失敗後仍能取回String追加內容。Any取回的是已知確切型別；有固定資料集合時可用enum，有共同業務能力時可用相應trait，而需要保留可擴充payload再辨識時，才承擔這份型別判斷。
