# 1.6 依訂單大小選擇運費

上一節固定收 20 元運費。現在規則改成：商品小計至少 300 元免運，低於 300 元收 20 元；數量為零時不收任何費用。輸入仍是單價與數量，函式仍交出總額，但計算中需要選擇不同路徑。

本節的訂單輸入限制在非負的小整數，且相乘與相加都不會超過 `i32` 範圍。這讓我們專注在選擇規則；接到外部資料時，如何表達無效輸入會在錯誤處理章學習。

## 條件是一個 bool

**比較運算**把兩個值拿來比較，得到 `bool`。`subtotal >= 300` 在小計為 300 或更大時得到 `true`，其他時候得到 `false`。`>=` 是大於等於，`>` 是大於；相對的有 `<=`、`<`。`==` 判斷相等，`!=` 判斷不相等。注意 `=` 是指派或提供初始值，`==` 才是比較。

`if 條件 { 工作 } else { 另一項工作 }` 會先算條件：若為 `true`，執行第一個 block；若為 `false`，執行 `else` 的 block。條件必須是 `bool`，Rust 不會自動把非零數字當成 `true`。若為 `false` 時沒有工作要做，可以省略 `else`。

`if` 本身也是 expression。要用它算出一個值，兩個分支都提供相同型別的尾端值，例如都給 `i32`。這樣 `let shipping = if ...;` 才能得到明確的運費數字；不能一邊交出數字、另一邊只顯示文字，卻把它們當成同一種結果。

## 提早交出結果

數量為零時已經知道總額是零，不需要再走小計與運費流程。`return 值;` 會立刻結束當前函式，將那個值交給呼叫者；函式後面的工作不再執行。它與前節最後一個 expression 都能回傳結果，只是 `return` 可以在函式中途結束。

完整程式末尾還會用到**布林邏輯**：`&&` 要求兩邊都為 `true`，`||` 只要其中一邊為 `true`，`!` 則反轉一個布林值。`price >= 0 && count >= 0` 因而表示單價與數量都非負。`&&` 在左邊已是 `false` 時不執行右邊，`||` 在左邊已是 `true` 時不執行右邊，稱為短路判斷。此例的右邊只是比較，不會額外改動資料。

現在依序看三項工作：空訂單提前結束；有商品就算小計；再依 300 元門檻選運費。`main` 則在顯示三筆總額後，檢查材料是否符合非負條件：

```rust
--8<-- "examples/ch01-basics/examples/conditions.rs"
```

```bash
cargo run -p ch01-basics --example conditions --locked
```

```text
小訂單=180，大訂單=360，空訂單=0
材料符合非負數條件
```

沿著同一個函式追蹤：80×2 得 160，未達門檻，加 20 得 180；120×3 得 360，運費選 0；數量為零則在第一個分支直接交出 0。這三組材料讓免運、收費、空訂單三條路徑都可見。

## 多個門檻的順序

超過兩種情況時，可以使用 `else if`：前一個條件不成立才檢查下一個，第一個成立的分支執行後就不再往下。假設運費改成「至少 500 免運、至少 300 收 10、其他收 20」，應先檢查 500，再檢查 300。若先把所有至少 300 的訂單接走，500 的條件就沒有機會處理那些訂單。

請先自己寫 `shipping(subtotal: i32) -> i32`，分別用 299、300、500 驗證門檻。每個分支都交出一個運費數字，呼叫後再顯示，讓「決定答案」和「顯示答案」保持分工。

完成後可對照 [參考程式](https://github.com/birdhackor/learn_rust/blob/main/examples/ch01-basics/examples/conditions_solution.rs)，或執行 `cargo run -p ch01-basics --example conditions_solution --locked`。你應得到 20、10、0。

下一節要一次保存數個有關係的數字。它們將是迴圈與後續資料處理的材料，而不需為每個值取一個新名稱。
