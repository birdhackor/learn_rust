## 3.1–3.3 的範例順序與限制

- 3.1 main 只使用數字 enum 的形態與 match；借用 pattern 在正文教清楚 &i32 後才進 borrow_patterns。branch_patterns 的兩種 Quote 是為單一條件工作明確簡化的資料模型，正文交代省略拒絕代碼的原因。
- 3.2 全部以可推導的具體值教標準 enum，不先寫完整角括號型別。Some/None 的 if 分支提供數字線索；Ok/Err 保存 i32 與自訂 DivideError。
- 3.3 先 Holder<T>/hold<T>，再 Option<i32>/Option<bool>/Result<i32,DivideError>。未知 T 不算術、不輸出；不讓函式簽名先使用尚未介紹的泛型語法。
- 所有練習答案都只用前文與本節已先教的概念；不使用 Debug/derive/chars/iter/closure/unwrap/?/Box/dyn。只對取出的數字或 bool 作當前已教的 assertion，不要求自訂 enum 的比較能力。
- 故意失敗原始碼各有相鄰 .expected：missing_variant=E0004；generic_same_type=E0308。這些不加入 Cargo 的正常範例目標。

### 定向 Clippy 政策

root 核准以本早期 package 的 Cargo.toml `[lints.clippy]` 將 `manual_map` 設為 allow。原因：selected_byte_len 保留已教的 match；Clippy 建議的 Option.map closure 到第 6 章才教。這是作者工具政策，沒有放寬 Rust 編譯、執行、測試或其他 warning，也沒有修改根 check 的 `-D warnings`。本章未展示整個 manifest，政策不塞入學生概念段落。question_mark 沒有設定 allow，因為最終版不需要；其餘 lint 仍依根檢查。
