## 官方 API 查證結果

當日 docs.rs 顯示 `clap 4.6.7`、`serde_json 1.0.154`、`tempfile 3.27.0`；std 文件為 `1.99.0`。這些是**研究時看到的版本**，最終使用版本與 lock 由 root 統一決定，不由作者擅自更新共享 manifest。

### 文字與 byte I/O

- [`fs::read_to_string`](https://doc.rust-lang.org/std/fs/fn.read_to_string.html) 讀完整檔案，成功值為 `String`；不存在、讀取失敗或內容不合法 UTF-8 都可能回傳 `io::Error`。函式也接受已教的文字路徑；`Path` 的完整角色在 7.5 才需要。
- [`Read::read`](https://doc.rust-lang.org/std/io/trait.Read.html) 接收 `&mut [u8]`，回傳實際讀到的 `usize`。`n < buffer.len()` 不等於 EOF；非空 buffer 的 `Ok(0)` 是本章停止讀取的條件。僅使用 `buffer[..n]`，不讓舊 buffer 尾端進入結果。手寫讀取迴圈處理 `Interrupted` 再重試。
- [`Write`](https://doc.rust-lang.org/std/io/trait.Write.html) 的 `write` 回傳已寫入的 byte 數，短寫是正常成功；`write_all` 才負責重複寫到完成或失敗。`flush` 推送中間 buffer，不宣稱它保證落到永久儲存裝置。
- 初次自訂 reader 可以用小型 `struct` 與 `impl Read` 展現固定短讀取；先逐項教它的狀態、buffer 與 `read` 契約，不把 helper 當黑箱。不引進 `Cursor` 的額外泛型或其他未教測試工具。

### path 與行程

- [`Path`](https://doc.rust-lang.org/std/path/struct.Path.html) 是借用的路徑表示，`PathBuf` 是 owned；選用 `as_path()`／`as_os_str()` 等明確借用方法，避免依賴尚未介紹的 `Deref`。
- `Path::to_str()` 的結果為 `Option<&str>`，失敗不能假定原生路徑無效。`display()` 供 `Display` 格式化，可能以替代字元呈現；它的結果不是路徑身分，不能當唯一鍵或用它重建原生路徑。本章避免 `to_string_lossy()` 的 `Cow` 型別。
- [`args_os`](https://doc.rust-lang.org/std/env/fn.args_os.html) 的 iterator 產生 `OsString`；第一項按慣例是程式名稱，不能宣稱它必定是真正執行檔路徑。不使用遇到不合法 Unicode 可能 panic 的 `args()` 路線。
- [`ExitCode`](https://doc.rust-lang.org/std/process/struct.ExitCode.html) 可由 `main` 回傳，適合正常完成清理再結束；先教 `SUCCESS`、`FAILURE` 與 `From<u8>` 的用途。若談 `process::exit`，必須指出它立即停止、不執行當前 scope 的正常清理；本章整合版優先使用 `ExitCode`。
- [`Command::output`](https://doc.rust-lang.org/std/process/struct.Command.html) 執行並等待子行程，收集 stdout／stderr 到 byte `Vec`。`Ok(Output)` 不代表子行程成功，還需檢查 `Output.status`；未能啟動等 I/O 失敗才是 `Err`。
- [Cargo environment variables](https://doc.rust-lang.org/cargo/reference/environment-variables.html) 的 `CARGO_BIN_EXE_<name>` 可定位 integration test 使用的執行檔；使用 `env!` 或 `std::env` 前先教選定方案的具體契約，並實際執行驗證，不以 `target/debug` 路徑猜測。

### clap 與 JSON

- `Parser::try_parse_from` 的輸入為 `IntoIterator<Item=T>`，`T: Into<OsString> + Clone`。在 7.5 先教 `OsString::from` 的具體轉換，在 7.6 解釋這個選定方法的輸入元素契約。可先用 owned `OsString` 陣列，避免暗中增加文字轉換與自動轉型。
- `#[derive(Parser)]` 需要 dependency 的 `derive` feature。`#[arg(long)]` 對 bool 欄位產生開關；對 value 欄位產生需跟值的選項。每個 attribute 先說清它改變的 parser 行為。
- [`clap::Error`](https://docs.rs/clap/latest/clap/error/struct.Error.html) 也承載 `--help`／`--version` 的顯示請求，因此 `Err` 不都代表使用者做錯。`use_stderr()` 與 `exit_code()` 可區分顯示 stream 與結束結果；`exit()` 會立即停止。`try_parse_from` 先保留錯誤作測試，整合時另外教正常回傳 `ExitCode` 的處理。
- `serde_json::from_str<'a,T>` 需要 `T: Deserialize<'a>`；這是 4.5 的 lifetime 與 6.2 的 trait 型別材料可支持的選用介面。owned struct 不借用輸入 JSON，函式回傳後可獨立持有結果。**不得展示 `DeserializeOwned` 或 `for<'de>`，它們要等 10.3。**
- Serde `Serialize` 定義轉成格式所需的能力，`Deserialize<'a>` 定義從輸入解碼的能力；JSON 是 `serde_json` 處理的資料格式，不能把 Serde 與 JSON 當同一件事。`serde_json::Error`、`to_string_pretty` 的輸入／輸出與可能失敗先教再用。
- `TempDir` 在正常離開 scope 時嘗試清理，失敗會被忽略；選用 `close()` 可取得清理錯誤。測試必須保留 owner 到子行程結束；不能呼叫 `process::exit` 期待同樣清理。完整 `Drop` 實作留到 8.2，這裡教此型別的使用契約。

補查 7.1–7.2 實際選用命令：[cargo update](https://doc.rust-lang.org/cargo/commands/cargo-update.html)、[cargo doc](https://doc.rust-lang.org/cargo/commands/cargo-doc.html)、[rustdoc 的 doc tests](https://doc.rust-lang.org/rustdoc/write-documentation/documentation-tests.html)。Rust 1.99 的 `cargo update --help` 使用 positional package spec，正文採 `cargo update clap`，不沿用舊教材的 `-p` 寫法。`cargo doc --no-deps --open` 建文件並請求瀏覽器，沒有執行文件例子；簡單 doc test 的 `main` 外框由工具補上，不需未教的 Result helper。
