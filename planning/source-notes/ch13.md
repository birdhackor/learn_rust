## 需要核對的契約與例子邊界

- std 文件為 Rust 1.99.0。Pin 是 library contract，不是 compiler 讓原值從此不可移動的魔法；safe API 的限制和作者 unsafe 責任同時成立。`Unpin` 取決於 pointee 的型別，不取決於 Box handle 是否 Unpin。
- `Pin<Box<T>>`、`Pin<&mut T>`、`as_mut`／`as_ref`／`get_mut`、`Box::pin` 必須在第一次 code 之前分別給用途／借用／回傳結果。使用 `get_unchecked_mut` 或 projection 必須就具體欄位證明不把被要求 pinned 的東西移走；不靠「只改一個 field」泛稱安全。
- pinning 的 guarantee 持續到 Drop；不能在 destructor 內移動 address-sensitive 欄位，也不能讓 storage 在 Drop 前就被重新使用。普通lifetime有效性並不能替代穩定地址契約。
- `Future::poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>` 的 receiver、lifetime placeholder、associated Output 都有實際先備或本節介紹後才出現。`Poll::Pending` 表示目前沒有完成結果；Wake 是通知任務可被重新 poll，不直接代替計算或保證下一次一定 Ready。
- Future 完成後 executor 不再 poll；Future implementor 仍不能因為 repeated safe poll 就出現 UB。輸出中如果有 Result，Ready(Err) 仍是 Future 完成。
- 若自製 future 存 Waker，保存最近一次 Context 的 Waker，readiness 檢查與登記需要防止「事件已到、卻睡著」的 race；採用第 10 章已懂的同一 Mutex 保護二者。wake 在鎖外觸發，避免重入或鎖依賴。輔助 thread／channel 的動作也必須已教，不用 sleep 猜執行次序。
- 一個有限教學 executor 只展示「第一次 poll→Pending→收到通知→再 poll→Ready」。不宣稱能執行需要 Tokio I/O／timer reactor 的任意 future，不將所有 async 的低層行為都說成沒有外部工作發生。
- tests 以受控通知和真實狀態變化驗必要關係，不以 fixed sleep 或公開網站觀察結果。當前研究並沒有進行 code／Miri／visual 驗證。
