## 官方契約與具體 API 陷阱

本次 std 文件標示 Rust 1.99.0；寫作實際程式還要由固定工具鏈執行驗證。

### 8.1：Sized／DST／Box

查核：[std boxed](https://doc.rust-lang.org/std/boxed/index.html)、[Book 20.3](https://doc.rust-lang.org/book/ch20-03-advanced-types.html)。

- `Sized` 是型別大小在編譯時可知的能力；`str`／`[T]` 的資料長度取決於值，`&str`／`&[T]` 等間接表示自身仍有可知大小。
- 泛型 T 通常有隱含 Sized 要求；`?Sized` 放寬這項要求，不表示所有 T 一定是 DST，也不是「不安全」註記。
- `Box::new(value)` 取得 value，對本章非零大小模型將它放到 owned heap 配置；Box 自身也可以存於其他結構／heap，不必然在 stack。
- 單一 pointer 表示保證適用 `T: Sized`，不能不加限定套到 `Box<str>`／`Box<[T]>`／`Box<dyn Trait>`。
- `Box<T>` 不等於「比借用更好的 pointer」；它改變了 ownership 與存放方式。成本比較須包含配置、釋放與間接存取，不以示意聲稱普遍效能優勢。
- 示意遞迴資料只追蹤有限配置關係，不指定 enum 精確 layout；raw pointer／allocator／C 互操作完全留後章。

### 8.2：Drop

查核：[std Drop](https://doc.rust-lang.org/std/ops/trait.Drop.html)、[std mem::drop](https://doc.rust-lang.org/std/mem/fn.drop.html)。

- `Drop::drop(&mut self)` 是 destructor 中的自訂部分；之後仍有自動清理欄位的部分，不要在自訂 drop 裡手動再釋放本來已有 ownership 的欄位。
- 局部變數通常以宣告反序清理，struct 欄位依宣告順序。兩種順序不可合併成「所有東西都是反序」。
- `std::mem::drop(value)` 取得值；對非 Copy 值是 move，函式返回前正常清理。drop reference／Copy 值不會因此銷毀原資料。
- 實作 Drop 的型別不可同時 Copy。借用最後使用結束與 destructor 的觸發是不同問題；本章示例限制為容易追蹤的局部 scope。
- 當前 std 的完整 trait 摘要還列了 nightly-only `pin_drop`。8.2 只教穩定 `drop` 的使用契約，不能貼整個摘要順便引入未教 Pin，也不稱 pin_drop 是本工具鏈可用穩定介面。
- 不作無條件保證「Rust 不洩漏」；後面的 strong cycle 仍可能保留資源。更深入的 forget／abort 路徑未作本節必要程式。

### 8.3：Deref

查核：[std Deref](https://doc.rust-lang.org/std/ops/trait.Deref.html)、[Book 15.2](https://doc.rust-lang.org/book/ch15-02-deref.html)。

- `Target` 是該 Deref 實作選定的借用目標型別；`deref` 回傳借自 self 的 `&Self::Target`，不是取得內部值 ownership。
- 必須引用 6.2 已完成的 associated type 與 8.1 的 `?Sized`，才可展示完整 Deref 定義。`String` 的 Target 是 str，Vec 的 Target 是 slice，回收前文 `as_str`／`as_slice`。
- Deref coercion 的主要具體用法是把 `&T` 借用為 `&Target`；不代表泛型 bound 會把任何 wrapper 視為 Target 的 trait implementor。
- method 查找可能沿 Deref 取得借用目標方法；與值的 ownership／trait 實作是不同機制。先以熟悉函式參數演示，再教當前需要的 method 查找。
- `DerefMut` 需要獨立契約；不能從 shared reference 自動得到 mutable reference。
- 教學 wrapper 不代表所有 newtype 都適合實作 Deref；公開的自動轉換、方法名稱衝突與成本是設計承諾。

### 8.4–8.5：bounds／dyn

查核：[Reference lifetime bounds](https://doc.rust-lang.org/reference/trait-bounds.html#lifetime-bounds)、[Reference trait object](https://doc.rust-lang.org/reference/types/trait-object.html)、[Reference dyn compatibility](https://doc.rust-lang.org/reference/items/traits.html#dyn-compatibility)、[Reference default object lifetimes](https://doc.rust-lang.org/reference/lifetime-elision.html#default-trait-object-lifetimes)。

- `'a: 'b` 描述 `'a` 至少涵蓋 `'b` 的有效範圍；`T: 'a` 限制 T 內的 lifetime，不能推成值「必須實際存活那麼久」。
- `&'static T` 是對資料的長效借用；`T: 'static` 不包含不滿足 static 的借用。owned String 可及早 drop，owned borrowed struct 仍可能不符合 static。
- dyn 是被遮住具體型別後保留指定能力的 DST；借用／Box handle 還需要對象位址與 dispatch 資訊。圖可以顯示角色，不指定 vtable 的私有排序或 ABI。
- 8.5 先使用 `&self`／`&mut self` 與已教的 Box receiver 作有限契約。不能搬整份包含 Rc／Arc／Pin／async／C-variadic 的 dyn compatibility 清單當必要先備。
- dyn compatibility 不等於「所有 method 都不准有任何泛型」：method lifetime parameter 可存在，`where Self: Sized` 的非 dispatch method 也另有規則。本文只演示代表性可用與不可用 case，完整進階規則有對應前置後再回收。
- `Box<dyn Trait>` 用於型別簽名時通常預設 object bound 為 static；`&'a dyn Trait` 的 object bound 通常由 reference 得到 `'a`。`'_` 與完全省略 object bound 的推導規則不同，必要對照在第一次需要處教。
- 具體／泛型／`impl Trait`／dyn 的比較使用相同任務；只說實際改變了異質集合／封裝／dispatch 的選擇，不虛構普遍效能結論。

### 8.6：Error

查核：[std Error](https://doc.rust-lang.org/std/error/trait.Error.html)的主契約、source、From<E> for Box。

- Error 需要 Debug 與 Display；source 預設 None，不是每個 Error 都一定含原因。
- `source` 回傳的 reference 仍借自 `&self`；`'static` 寫在 dyn 對象 bound，限制所遮住錯誤型別中的借用，不表示回傳 reference 能用到程式結束。
- 外層 Display 的資訊與 source 原因鏈分工，避免同一原因在每層文字與鏈裡重複展開。
- Box<dyn Error> 的 From 轉換需要 E: Error 加符合 object lifetime；先連回 5 章 From／Into／?，不能用未知 helper 消掉 bounds。
- `Send`／`Sync` 版 Box 不在此程式引入，等 thread 章教清需要再擴展。
- 不展示已 deprecated 的 cause／description，或 nightly-only provide／sources API。Error 有自己的 downcast 能力，但詳細 type identity 教學等 8.10；本節只做已知具體 source 追蹤。

### 8.7–8.8：Rc／Weak／Cell／RefCell

查核：[std rc](https://doc.rust-lang.org/std/rc/index.html)、[std Weak](https://doc.rust-lang.org/std/rc/struct.Weak.html)、[std cell](https://doc.rust-lang.org/std/cell/index.html)、[std RefCell](https://doc.rust-lang.org/std/cell/struct.RefCell.html)。

- Rc::clone 產生指向相同 allocation 的新 handle；Rc::downgrade 取得不保活 T 的 Weak；upgrade 成功時回傳新 Rc，之後由它保活 T。
- 最後 strong handle 消失時 T 被 drop；Weak 仍可讓 backing allocation 保留，兩者不能混稱「完全釋放」。Weak::new 不配置資料，upgrade 為 None。
- 8.7 循環問題先用圖解，RefCell 已教後再動態組合；避免把尚未教的 interior mutability 放進前節完整程式。
- Cell 以取出／替換值提供內部可變；get 僅在 T: Copy 時可用，set 可替換值且清理舊值。不要默默用要求 Default 的 take。
- RefCell.borrow／borrow_mut 回傳 Ref／RefMut guard，不是直接回傳普通 reference。Guard 包含 borrowing 活躍狀態，透過 Deref／DerefMut 才可操作內部值。
- Guard 正常在 scope 結束被清理；即使最後一次用 guard 已過，guard 若尚未 drop，執行期借用仍可能活躍。顯式 drop guard 或小 scope 可讓下一次借用成功。
- borrow 衝突可 panic；try_borrow／try_borrow_mut 回傳 Result。不展示未知 `.is_err()`／unwrap 作測試捷徑，除非前文確實教過；可用已教 match。
- shared reference 不保證內部資料永遠不可修改；安全 Cell／RefCell API 維持自己的契約，不需要本章實作 unsafe internals。

### 8.9：trait 設計

查核：[Reference coherence／orphan](https://doc.rust-lang.org/reference/items/implementations.html#trait-implementation-coherence)、[std Add](https://doc.rust-lang.org/std/ops/trait.Add.html)、Book 20.2–20.3。

- alias 是同一型別的另一名稱；newtype 建立型別邊界。用單位／資料身分任務解釋差別，而不是只比較語法。
- orphan 基本門檻是 trait 或實作中某個型別在本 crate，泛型實作仍有 uncovered type parameter 的位置限制；coherence 也禁止重疊，不把「有一個本地型別就一定合法」當完整規則。
- Add 有預設 `Rhs = Self`、associated Output，add 取得 self 與 rhs；只實作本節實際要用的數值 newtype，先教三項角色再給程式。
- newtype 不必自動公開所有 inner method；不以 Deref 繞掉剛建立的單位／介面限制。

### 8.10：Any

查核：[std any](https://doc.rust-lang.org/std/any/index.html)、[std Any](https://doc.rust-lang.org/std/any/trait.Any.html)。

- Any 的 bound 是 static。`&dyn Any` 的借用本身仍可很短；dyn 內的具體型別需滿足 static，不能裝含局部短借用的模型。
- downcast_ref／downcast_mut 是嘗試借用某個確切型別，回傳 Option；不是數值轉型，也不能用來查某型別是否實作任意 trait。
- Box<dyn Any>.downcast 取得 Box，成功回傳 Box<T>，失敗把原 Box 回傳在 Err；失敗沒有銷毀或轉換 payload。
- 對 Box 直接呼叫 type_id 可能取得 container 的身分；對 `&dyn Any` 才能問內部對象。先實際教 `&*boxed` 借用目標，再給需要辨認兩者的示例。
- 本章不用 TypeId 的排序／內部數字作資料格式；不展示 unchecked downcast 或 thread panic payload。10.2 在 thread 契約需要時再引用本節能力。
