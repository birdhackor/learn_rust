## Cargo 官方契約與必要前置

來源：[Workspace reference](https://doc.rust-lang.org/cargo/reference/workspaces.html)、[Profiles](https://doc.rust-lang.org/cargo/reference/profiles.html)、[Build scripts](https://doc.rust-lang.org/cargo/reference/build-scripts.html)。

### 9.1：從正在使用的 workspace 到共用設定

- `[workspace.package]` 與 `[workspace.dependencies]` 是 root 提供可繼承設定的位置；成員需明確 `*.workspace = true`，不是放進 root 後所有成員自動取得。
- 共用 dependency 的 features 與成員要求會相加。`default-features` 繼承規則與 edition／Rust 版本有關；**Rust 1.99 + edition 2024 的成員可覆寫 root 的 default-features**。不可抄舊教材寫成所有版本一律不能覆寫。本章最好選無此歧義的設定，不額外增加版本史負擔。
- profile 設定從 workspace root 讀取；成員 manifest 的同名 profile 不生效。`dev`／`release` 是編譯設定組合，不是不同語言語意的許可。
- 9.1 先教 `#[cfg(...)]`、feature 與 target 的判定範圍，再展示對應 Rust source。`cfg!` 產生 bool，與用 attribute 排除程式的行為不同，若兩者都用就各自先教。

### 9.2：建置 script 也只是另一個 Rust 程式

- Cargo 先將 package root 的 `build.rs` 編譯成供 host 執行的程式，再執行它，最後編譯 package；它與主要 crate 的 `main` 是不同入口。
- `println!` 在此傳送 Cargo 捕捉的協定訊息；選用 `cargo::...` 前逐項解釋指令。它不是最終 CLI 的 stdout 報告。
- **host 與 target 要分開：**script 中 `cfg!(target_os = ...)` 看的是執行 script 的 host。要判 package 編譯目標，讀 `CARGO_CFG_TARGET_OS` 等環境值。
- `cargo::rerun-if-changed`／`rerun-if-env-changed` 說明哪些輸入變動使 script 重新執行。script source／dependency 變更的重新編譯與外部輸入觸發的重新執行不是同一動作。
- 若生成檔案，只寫 `OUT_DIR`；此目錄不保證每次為空。`include!`、`env!`／`concat!` 或 `std::env::var` 若出現，都須先教選用 API 的具體用途與回傳結果。
- `[build-dependencies]` 供 script 使用，與主 crate 的一般 dependencies 分開；本章不需要 `cc`。完整編譯／連結 C 的流程留 12.6。

## walkdir：路徑、metadata 與錯誤

已讀：[WalkDir](https://docs.rs/walkdir/latest/walkdir/struct.WalkDir.html)、[DirEntry](https://docs.rs/walkdir/latest/walkdir/struct.DirEntry.html)、[walkdir::Error](https://docs.rs/walkdir/latest/walkdir/struct.Error.html)。

### 不可忽略的 root link 特例

`follow_links(false)` 的預設不等於拒絕 root symbolic link。`WalkDir::new` 的 root 預設仍可跟隨；2.5.0 提供 `follow_root_links(false)` 控制它。最終實戰 A 的規則要求 **root 是 link 時直接設定錯誤**，因此要在開始遍歷前先用 `fs::symlink_metadata` 驗證 root，不能單靠遍歷設定再跳過項目。

`DirEntry::file_type()` 是該項目的類別資訊，不需額外系統呼叫；`DirEntry::metadata()` 可能失敗，其是否跟隨 link 取決於 walker 設定。`path()` 借用 Path；`into_path()` 移出 owned PathBuf。需要持有後續工作路徑時，先交代 ownership 選擇。

遍歷 iterator 的每項為成功 entry 或 walkdir error。遇錯仍可處理下一項；不可用 `filter_map(Result::ok)` 抹除錯誤並宣稱完整掃描。`Error::path()` 為 `Option<&Path>`，未必有路徑；錯誤紀錄需允許未知 path，保留動作與原因。

### std filesystem 契約

已讀：[Metadata](https://doc.rust-lang.org/std/fs/struct.Metadata.html)、[symlink_metadata](https://doc.rust-lang.org/std/fs/fn.symlink_metadata.html)、[File](https://doc.rust-lang.org/std/fs/struct.File.html)。

- `metadata` 跟隨 link，`symlink_metadata` 看 link 本身；先解釋這個差異再作 root 判定。一般檔案、目錄與 link 的篩選責任不能藏在 helper。
- `Metadata::len()` 是 `u64` 的 byte 數；它與 `usize` 的 buffer 索引是不同角色。要計算指標時先教必要轉換與溢位處理。
- `Metadata::modified()` 回傳 `io::Result<SystemTime>`，不保證每個平台都有值；`SystemTime` 的比較角色在首次使用前介紹。將不可取得時間吞成 None 後宣稱已完整檢查變動是不成立的。
- 檔案可能被其他行程變更。持有 `File` 或 shared reference 不保證內容固定；前後 len／modified 比較只能揭露可觀察差異，不是完整快照證明。
- 掃描後、打開前再次核對可觀察 metadata；hash 前後、內容比較前後的失敗或變化列項目錯誤。僅先比較兩份 metadata、然後任意讀取，不滿足「讀取前後觀察」。
- 一般跨平台 File API 與 metadata 檢查不是抵抗惡意並行替換的安全隔離。正文承諾範圍保持 v2 的盡力而為與穩定目錄使用；不藉此加入平台專屬安全開啟 API 擴大專案。

### path 身分與 Unicode

沿用 7.5 的 PathBuf／OsString，不新增 `Cow`。核心保留原生 PathBuf；`display()` 可能失真，只供呈現，不作 HashMap key 或重建路徑。最小實戰接受 `to_str()` 成功的路徑；失敗列項目錯誤與可辨識 debug 呈現，跳過該項。寫 JSON 前轉換時仍不得 `unwrap` 假定它成功。

路徑／群組的「穩定排序」是在固定平台、同一組可處理輸入下有固定順序，不宣稱 Unix 與 Windows 的所有原生 path 排序完全相同。hard link 的多個 path 仍按 v2 算不同路徑，不合併成檔案 inode。

## blake3：分塊與真正 bytes 比較

已讀：[Hasher](https://docs.rs/blake3/latest/blake3/struct.Hasher.html)、[Hash](https://docs.rs/blake3/latest/blake3/struct.Hash.html)。

- `Hasher::new` 建立空狀態；`update(&[u8])` 加上目前有效 bytes，依序呼叫得到串接輸入的 hash；`finalize(&self)` 產生 32-byte `Hash`，不消耗 hasher。
- `Hash` 支援相等比較、作 HashMap key 與 Display；當前最小 API 不需 `to_hex()` 回傳的額外 ArrayString 型別。`Hash` 與標準 `std::hash::Hash` trait 名稱相同、角色不同，首次需要時明確區分。
- 不使用 `update_mmap`、`update_rayon` 或 `traits-preview`；這些會加入 features／並行／額外介面與取捨，不是千行練功題必要內容。
- digest 是固定長度摘要，相等 hash 只能形成候選，不能代替真正相同內容。大小先分組、hash 再縮小候選、byte 比較最後判定，三步回答不同問題。
- **候選桶可能有多個真正內容群組。**新候選要與各群組的代表比較，成功才加入該群組；全部不同就建立新群組。不得只跟桶第一個檔案比，否則會漏掉桶中後面的相同檔案。
- byte 比較沿用 7.4 的短讀取契約：左右 reader 可讀到不同的短長度，所以一次 `read` 的 `n_left != n_right` 不能判內容不同。先分別將 buffer 填至容量或 EOF，或保留各 reader 的待比較段，再比較有效資料與是否都結束。
- 控制測試可把相同假 digest 放入候選桶，驗證真正分組；這不是宣稱找到 BLAKE3 的真實碰撞。假 reader 的每次最多讀幾個 bytes／何時失敗必須明示並先教。
- 指標 `(路徑數−1)×檔案長度` 是按 path 的重複內容量，包含 hard links；不是實體磁碟可回收量。選用 `checked_mul`／`checked_add` 或較寬整數前先教用途，避免大檔案時 silent overflow。
