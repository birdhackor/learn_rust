## 已確認的前置修正

研究官方 `TryFrom` 與 `FromStr` 的宣告時發現：`TryFrom` 使用 `type Error`／`Self::Error`，`FromStr` 使用 `type Err`／`Self::Err`，原 v2 把 associated type 的介紹排在 6.2。因此若照標題直接寫標準 impl，會違反範例只能用已教內容的要求。

root 已採納的處置：**在 5.4 首次實作 `TryFrom` 前教 associated type 的最低意義與語法**：trait 提供一個型別位置，每個 impl 決定該位置的具體型別；`type Error = ...` 指定這次轉換的錯誤型別，`Self::Error` 在該 impl 指向這個選擇。5.5 用 `type Err` 回收此概念，6.2 再擴展 associated type 的介面設計，不能聲稱讀者此前已懂其完整範圍。5.5 若展示 `ToOwned` 的 `Owned`，同樣需依這段實際最低解說銜接。

這是作者研究觸發的必要前置修正，非首次讀者發現。現階段只記錄，不自行改正文或宣稱已驗收。

| [Display](https://doc.rust-lang.org/std/fmt/trait.Display.html)：trait method、`{}`、Debug 的用途差別、完整性／可解析性、Errors 契約 | `Display` 用於讀者看的文字，不能 derive；impl 將內容寫入呼叫者提供的 Formatter。**只在 Formatter 回報寫入失敗時回傳 fmt error**，不是拿它表示資料不合法。Display 文字未必可逆，不能不加條件就把 `parse(display(value)) == value` 當普遍性質 |
| [Formatter](https://doc.rust-lang.org/std/fmt/struct.Formatter.html)：角色、lifetime parameter、`write_str`／`write_fmt` 的存在 | 5.3 需要用已有 4.4 的 `'_` 解釋型別中省去命名的 lifetime，再解釋 `&mut Formatter<'_>` 是借入的輸出介面。先用 `write!` 的具體契約，不搬所有格式旗標／padding／precision，也不偷渡建造 Arguments 的完整機制 |
| [fmt::Result](https://doc.rust-lang.org/std/fmt/type.Result.html) 與 [fmt::Error](https://doc.rust-lang.org/std/fmt/struct.Error.html)：alias／取消格式化與無額外錯誤資訊 | 展開為 `Result<(), fmt::Error>`；成功值 `()` 接回 1.5。不能以 `Err(fmt::Error)` 表示自訂 enum 的輸入驗證失敗。單個 `write!` 作 method 最後表達式即可，不用超前 `?` |
| [write!](https://doc.rust-lang.org/std/macro.write.html)：接受輸出位置、格式字串與參數、回傳 writer 的結果 | 對 Formatter 使用 `write!(f, "...", ...)`；先教它相對 `println!` 的輸出位置差別。官方其他示例有 `io::Write`、`Box<dyn Error>`、`?`、`no_std`，全部不搬入 5.3。如需對 String 寫入，必須先教必要 `fmt::Write` trait import，不能默默加 `as _` |

## 候選 SVG 圖意

1. **5.1／5.6：誰決定失敗政策。** 下層驗證函式回傳 `Err` 到上層，上層分成報告、替代值或停止；箭頭表示回傳值，區別與正常成功流的路徑。沿用正文裡同一函式名稱，無 I/O／thread 等新材料。
2. **5.6：`?` 的兩條路。** `Ok(value)` 繼續到下一行；`Err(error)` 經已學的 `From::from` 回到當前函式呼叫者。圖上標明「整個函式早退」，不是只離開 match／block，並與相鄰的手動版 match 對照。
