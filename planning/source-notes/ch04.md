## 官方技術契約查核

本次官方 std 頁面標示版本為 Rust 1.99.0，與專案固定工具鏈一致。

| API／能力 | 實際已讀來源與部分 | 寫作時必須保留的契約 |
| --- | --- | --- |
| `Clone` | [std Clone](https://doc.rust-lang.org/std/clone/trait.Clone.html)：基本說明、derive、與 Copy 的差別 | `.clone()` 明確產生新值，具體底層資料是否複製依型別決定；derive 逐欄呼叫 Clone。4.2 可展示 String 的獨立文字副本與 shared reference 仍指向同一資料，不先展示 Rc／Arc |
| `Copy` | [std Copy](https://doc.rust-lang.org/std/marker/trait.Copy.html)：move／copy、derive、允許條件 | Copy 是隱含 bitwise 複製語意，必須也有 Clone；自訂數值 struct 不自動 Copy。String／Vec 的 heap ownership 不可只複製持有資訊，所以不能 derive Copy |
| `Eq` | [std Eq](https://doc.rust-lang.org/std/cmp/trait.Eq.html)：比較契約與 derive | 以已教 PartialEq 為基礎，增加每個值都與自己相等的要求；Eq 沒有新方法。選用整數／String 鍵，避免把浮點 NaN 示例引成額外先備 |
| `Hash` | [std Hash](https://doc.rust-lang.org/std/hash/trait.Hash.html)：derive、Hash 與 Eq、portability | 相等鍵必須有相等 hash；相同 hash 不代表鍵相等。derive 與相等判定必須使用一致欄位。測試不固定具體 hash 數字或假定跨版本穩定；不先實作自訂 Hasher |
| `Borrow` | [std Borrow](https://doc.rust-lang.org/std/borrow/trait.Borrow.html)：owned／borrowed 表示、Eq／Hash 一致要求與 HashMap 查詢用途 | String 可作 str 的借用表示，查詢不必建立 owned String。Borrow 不只是任意取得某個 reference；作鍵的 borrowed 表示需保持 Eq／Hash 行為。4.3 先教具體 String／str 情況，不貼含 `?Sized` 的泛型定義 |
| `HashMap::get`／`get_mut`／`insert` | [std HashMap](https://doc.rust-lang.org/std/collections/struct.HashMap.html)：鍵契約、get、get_mut、insert 說明 | get 回傳借自 map 的 `Option<&V>`；get_mut 回傳 `Option<&mut V>`；查詢文字 reference 不會被 map 保留為回傳值來源。insert 取得鍵和值，回傳舊值或 None；已存在等值鍵時替換值而非必定替換鍵。讀取借用仍在用時不能修改 map |
| lifetime elision／`'_` | [Rust Reference：Lifetime elision](https://doc.rust-lang.org/reference/lifetime-elision.html)：函式與 method 規則、placeholder | 每個省略的輸入 lifetime 分開；唯一輸入 lifetime 可接輸出；method 的省略輸出通常接 `&self`／`&mut self`。`'_` 交由相同規則推導，不是延長存活或任意 lifetime |
| `'a: 'b`／`T: 'a` | [Rust Reference：Trait and lifetime bounds](https://doc.rust-lang.org/reference/trait-bounds.html#lifetime-bounds)：lifetime bounds 與 implied bounds | `'a: 'b` 是 `'a` 至少涵蓋 `'b` 要求的有效範圍，不是執行秒數。只有當本章代表性例子確實需用才教相應關係；完整型別 outlives、static 及 HRTB 留 8.4／10.3 |

## 本章預定寫法與等待條件

這是等待前文交付前的教學選型，不能當作前置已驗收證據。

- 4.1：兩個具有不同欄位的數值資料型別，要供同一小流程取得量測值；自訂單一方法 trait，再定義泛型 bound，最後用已教的測試驗證不同實作。`where`／多個 bounds 僅在實際有需求時引入。
- 4.2：同一小資料模型逐項增加 `Debug`、`PartialEq`、`Clone`／`Copy` 能力。每個 attribute 之前先說清會啟用的操作、生成的欄位行為與限制；測試與正文採相同順序。
- 4.3：從既有文字清單統計到 `HashMap<String, usize>`。先按已知字詞查結果，避免 HashMap 迭代、排序與固定 Debug 順序的隱藏先備。可用 `get_mut` 搭配 `match` 更新既有項目，缺鍵時才 insert；先完整交代兩個呼叫契約。
- 4.4：單一來源省略 → 多來源回傳需要簽名契約 → 不同資料存活範圍 → 僅一來源的較精確契約 → owned 回傳。必要的 outlives 有明確任务才補；annotation 絕不負責延長值的存活。
- 4.5：先只有一個 borrowed 欄位，後增一個獨立 borrowed 欄位，讓兩個 lifetime 的用途可見；用 method 比較省略輸出與明確欄位來源。待前文核對後決定實際 API、編譯失敗用例與 SVG。
- 圖解候選：4.1 共同行為與不同實作對同一流程的連線；4.3 query／map／回傳 reference 的三個不同身分；4.4 兩個來源與輸出可用區段；4.5 struct reference 欄位對來源資料的箭頭。必要圖貼正文原位置，並由整合者實際檢查桌面／手機版面。
- 尚待取得：第 1–3 章實際已教文字／程式版本、完整 API 位置與編譯失敗驗收機制。未取得前不寫本章正文、helper、測試、練習或答案。
