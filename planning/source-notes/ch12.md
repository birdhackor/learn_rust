## 英中教材實際閱讀與取捨

| 範圍 | 實際閱讀的來源與內容 | 值得學習的教法 | 本書需調整或避免的部分 |
| --- | --- | --- | --- |
| 12.1 GAT | [Rust Reference：associated types／GAT 與 required where clauses](https://doc.rust-lang.org/reference/items/associated-items.html#associated-types)：`Lend`／`ArrayLender`、每次借用帶入 lifetime，以及 `Self: 'a` 的來源 | 從已懂的 associated type 延伸成「型別的選擇還需要這次借用的 lifetime」，用一個有限借出內部資料的介面呈現差異 | 不直接跳進通用 LendingIterator、adapter 或未教的 const generics。`where Self: 'a` 必須連回借用 self 的有效性，而不是說「編譯器要加就加」。沒有找到可如實宣稱已讀的繁中 GAT 專章；技術依據採官方 Reference，本章中文敘述自行建立 |
| 12.2 variance | [Rustonomicon：Subtyping and Variance](https://doc.rust-lang.org/nomicon/subtyping.html)：長借用替換短借用、`assign` 的問題、reference／Cell／function pointer 的方向表；[語言聖經：variance 與 PhantomData](https://raw.githubusercontent.com/sunface/rust-course/main/src/too-many-lists/production-unsafe-deque/variance-and-phantomData.md)：同一 `take_two` 對 reference／Cell／Vec 的比較 | 保持同一 lifetime 關係，只換包住資料的型別，讓合法替換與寫入可能導致的失效可見。function pointer 從「呼叫者能交什麼資料」推方向 | 中文原文由生產級 linked list 切入，帶入 NonNull／PhantomData／Drop check；本節不照搬。必須分開 `&'a mut T` 對 `'a` 的 covariance 與對 `T` 的 invariance，不能一律說 mutable reference 不可縮短 lifetime。HRTB 與普通 lifetime subtyping 也不可混為同一機制 |
| 12.3–12.4 raw pointer／unsafe | [英文 Book 20.1](https://doc.rust-lang.org/book/ch20-01-unsafe-rust.html)、[簡體 Book 20.1](https://kaisery.github.io/trpl-zh-cn/ch20-01-unsafe-rust.html)、[繁體 Book 19.1](https://rust-lang.tw/book-tw/ch19-01-unsafe-rust.html)：建立與存取 raw pointer、unsafe function 的契約、split_at_mut 的安全抽象 | 先區分「持有 pointer」與「透過 pointer 存取值」，再以具體借用切分需求說明 safe API 如何把使用者的責任縮小 | 不照搬任意整數地址 dereference，不要求讀者執行 UB 來看會不會崩潰。繁中版是較舊 edition；現在使用 `&raw const`／`&raw mut` 與 `unsafe extern`。`unsafe` 不關掉 reference 的檢查，也不等於「更快」。不能只由索引 assertion 宣稱全部 safety 條件已證完 |
| 12.3–12.4 safety 理由 | [Comprehensive Rust：Dereferencing Raw Pointers](https://google.github.io/comprehensive-rust/unsafe-rust/dereferencing.html)：同一局部值的 read／write 與逐項 SAFETY 理由；[新版課程 soundness 原始章節](https://raw.githubusercontent.com/google/comprehensive-rust/main/src/unsafe-deep-dive/rules-of-the-game/soundness-proof/soundness.md)：滿足 precondition 時不能觸發 UB | 把 assertion／型別／scope 實際保證的條件逐項列出，指認來源與還要由作者承擔的條件，不只在 unsafe 區塊貼「已確認」 | 使用官方契約修正泛稱「pointer 存在就禁止任何 reference」的過度簡化。教學採小而容易證明的單 thread 範圍；cross-thread data race、unsafe Send／Sync 等待第 10 章實際前置。官方新版網頁路徑本次未能開啟，已實讀其 GitHub Markdown，而非宣稱網頁可用 |

| 12.5–12.6 FFI | [Rustonomicon：FFI](https://doc.rust-lang.org/nomicon/ffi.html)：signature 宣告、buffer／length、safe wrapper、foreign resource destructor；[Comprehensive Rust：Unsafe External Functions](https://google.github.io/comprehensive-rust/unsafe-rust/unsafe-functions/extern-c.html)：extern 宣告與呼叫契約 | 先展示 C API 的實際資料與責任，再畫 Rust 呼叫、C 取得／配置、Rust 使用、C 釋放的流程；從 raw 介面收斂到有限 safe API | 不沿用需另裝 Snappy／C++ library 的設定，不使用 Vec capacity＋set_len 作第一個 wrapper。C 語法、型別、buffer 與 compiler／linker 都不能視為 Python 讀者先備。外部宣告不由 rustc 自動比對 C 定義；repr(C) 也不自動保證所有欄位適合 FFI |
| 12.6 C abs 教例的來源陷阱 | 上述英／簡中 Book 與 Comprehensive Rust 的 `safe fn abs(i32)` 宣告；[新版課程 abs Markdown](https://raw.githubusercontent.com/google/comprehensive-rust/main/src/unsafe-deep-dive/ffi/abs.md)也讀過其 c_int 對照 | 值得採用「先找 C signature，再對照 Rust 型別，再檢查契約」的順序 | 不能沿用「任意 i32 都可 safe 呼叫」的說法：C 最小負整數的絕對值無法以同型別表示時，abs 有 UB。改用本專案自帶、契約可完整交代的有限 C API；不需要讓此旁支主導正文 |

## 技術來源與必要 API 使用契約

本次 std 文件版本為 Rust 1.99.0。後續程式還須在專案固定工具鏈執行；測試通過不代替 soundness 理由。

- [Reference：Subtyping and variance](https://doc.rust-lang.org/reference/subtyping.html)核對 lifetime 替換方向。採 shared reference、mutable reference、`Cell`、function pointer 的具體例子；先教參數與回傳的角色，再介紹 covariance／contravariance／invariance 名稱。使用 `for<'a>` 時，須確認第 10.3 的實際正文已教該語法與能力。
- [Reference：Pointer types](https://doc.rust-lang.org/reference/types/pointer.html)、[std ptr：validity／alignment／pointer to reference／provenance](https://doc.rust-lang.org/std/ptr/index.html)核對來源與存取責任。pointer 不是只有一個整數地址；provenance 在本章解釋成「與來源 allocation 有關的存取資格」，不虛構完整且已定案的 aliasing 模型。
- [Reference：Behavior considered undefined](https://doc.rust-lang.org/reference/behavior-considered-undefined.html)核對 UB 與 soundness：safe caller 可觸發 UB 的 wrapper 就是 unsound，即使目前測試正常。read／write／reference 建立的條件不能只驗 `is_null()`；也包含 live allocation、有效值、alignment、aliasing 與資料競爭等。當前官方仍說完整 aliasing 規則未完全確定，正文不宣稱一張表涵蓋所有 unsafe Rust。
- [std slice::from_raw_parts_mut](https://doc.rust-lang.org/std/slice/fn.from_raw_parts_mut.html)、[from_raw_parts](https://doc.rust-lang.org/std/slice/fn.from_raw_parts.html)：整段同一 allocation、元素已初始化、正確 alignment、即使 len=0 仍 non-null／aligned、總大小不超過 `isize::MAX`、回傳 reference 的有效期間維持對應存取限制。從 raw pointer 生出的 lifetime 要綁回 host 的借用，不能憑回傳簽名製造 static。
- [std pointer](https://doc.rust-lang.org/std/primitive.pointer.html)：`add(n)` 的 n 是元素數量；in-bounds／one-past pointer 的形成與實際 dereference 分開判。型別的 `*`、操作的 `*`、`&raw`、slice `as_ptr`／`as_mut_ptr` 在第一次範例前各自解釋。只列與本章有限模型實際使用的 API，不貼整頁含 nightly 的摘要。
- [Reference：Type layout](https://doc.rust-lang.org/reference/type-layout.html)、[External blocks](https://doc.rust-lang.org/reference/items/external-blocks.html)：ABI（application binary interface）的呼叫規則與資料布局不同；`repr(C)` 固定此 struct 的 C 布局規則，不遞迴改變欄位自身的 Rust layout，也不保證 Rust String／Vec 可直接當 C struct 欄位。最小 C bridge 使用固定寬度整數／byte buffer／明確 length；pointer／ownership／free 契約逐一對照。
- [std CString](https://doc.rust-lang.org/std/ffi/struct.CString.html)、[CStr](https://doc.rust-lang.org/std/ffi/struct.CStr.html)：C 字串以 NUL 終止，Rust str 以 UTF-8 與 length 表示；CString::new 會拒絕 interior NUL。as_ptr 的借用不轉移 ownership，必須讓 CString 活到 C 最後一次存取。最小 bridge 可以 length buffer 為主要任務，但正文仍在使用前教足 C 字串與 buffer 的差別。
- [cc::Build](https://docs.rs/cc/latest/cc/struct.Build.html)：在 build-dependencies 放 cc，build.rs 呼叫 `Build::new`→`file`→`compile`，compile 產出 archive 與 link 指令；參數是 library 名稱，沒有路徑或手動加 lib 前綴。明確先教 builder 的 mutable method 回傳與工作目的，不能直接貼未解釋的連鎖。依 root 管理的固定版本核對後才入例子。
- [GCC：Overall Options](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)已實讀，作 C compiler／object／linker 分工依據。C source 到 object 與最後連結 Rust binary 的分工要可追蹤；讀者不用先學完整編譯器設計。

GNU C introduction／libc 的 pointer 與 allocation 原站本次回應 HTTP 503，因此沒有將這兩頁列為已讀。C 基礎正式撰寫前仍需補查可取用的 primary source，尤其 malloc／free、size_t／uint8_t 與 C string 的精確契約。
