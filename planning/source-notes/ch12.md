## 技術來源與必要 API 使用契約

本次 std 檔案版本為 Rust 1.99.0。後續程式還須在專案固定工具鏈執行；測試透過不代替 soundness 理由。

- [Reference：Subtyping and variance](https://doc.rust-lang.org/reference/subtyping.html)核對 lifetime 替換方向。採 shared reference、mutable reference、`Cell`、function pointer 的具體例子；先教參數與回傳的角色，再介紹 covariance／contravariance／invariance 名稱。使用 `for<'a>` 時，須確認第 10.3 的實際正文已教該語法與能力。
- [Reference：Pointer types](https://doc.rust-lang.org/reference/types/pointer.html)、[std ptr：validity／alignment／pointer to reference／provenance](https://doc.rust-lang.org/std/ptr/index.html)核對來源與存取責任。pointer 不是只有一個整數地址；provenance 在本章解釋成「與來源 allocation 有關的存取資格」，不虛構完整且已定案的 aliasing 模型。
- [Reference：Behavior considered undefined](https://doc.rust-lang.org/reference/behavior-considered-undefined.html)核對 UB 與 soundness：safe caller 可觸發 UB 的 wrapper 就是 unsound，即使目前測試正常。read／write／reference 建立的條件不能只驗 `is_null()`；也包含 live allocation、有效值、alignment、aliasing 與資料競爭等。當前官方仍說完整 aliasing 規則未完全確定，正文不宣稱一張表涵蓋所有 unsafe Rust。
- [std slice::from_raw_parts_mut](https://doc.rust-lang.org/std/slice/fn.from_raw_parts_mut.html)、[from_raw_parts](https://doc.rust-lang.org/std/slice/fn.from_raw_parts.html)：整段同一 allocation、元素已初始化、正確 alignment、即使 len=0 仍 non-null／aligned、總大小不超過 `isize::MAX`、回傳 reference 的有效期間維持對應存取限制。從 raw pointer 生出的 lifetime 要綁回 host 的借用，不能憑回傳簽名製造 static。
- [std pointer](https://doc.rust-lang.org/std/primitive.pointer.html)：`add(n)` 的 n 是元素數量；in-bounds／one-past pointer 的形成與實際 dereference 分開判。型別的 `*`、操作的 `*`、`&raw`、slice `as_ptr`／`as_mut_ptr` 在第一次範例前各自解釋。只列與本章有限模型實際使用的 API，不貼整頁含 nightly 的摘要。
- [Reference：Type layout](https://doc.rust-lang.org/reference/type-layout.html)、[External blocks](https://doc.rust-lang.org/reference/items/external-blocks.html)：ABI（application binary interface）的呼叫規則與資料佈局不同；`repr(C)` 固定此 struct 的 C 佈局規則，不遞迴改變欄位自身的 Rust layout，也不保證 Rust String／Vec 可直接當 C struct 欄位。最小 C bridge 使用固定寬度整數／byte buffer／明確 length；pointer／ownership／free 契約逐一對照。
- [std CString](https://doc.rust-lang.org/std/ffi/struct.CString.html)、[CStr](https://doc.rust-lang.org/std/ffi/struct.CStr.html)：C 字串以 NUL 終止，Rust str 以 UTF-8 與 length 表示；CString::new 會拒絕 interior NUL。as_ptr 的借用不轉移 ownership，必須讓 CString 活到 C 最後一次存取。最小 bridge 可以 length buffer 為主要任務，但正文仍在使用前教足 C 字串與 buffer 的差別。
- [cc::Build](https://docs.rs/cc/latest/cc/struct.Build.html)：在 build-dependencies 放 cc，build.rs 呼叫 `Build::new`→`file`→`compile`，compile 產出 archive 與 link 指令；參數是 library 名稱，沒有路徑或手動加 lib 字首。明確先教 builder 的 mutable method 回傳與工作目的，不能直接貼未解釋的連鎖。依 root 管理的固定版本核對後才入例子。
- [GCC：Overall Options](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)已實讀，作 C compiler／object／linker 分工依據。C source 到 object 與最後連結 Rust binary 的分工要可追蹤；讀者不用先學完整編譯器設計。

GNU C introduction／libc 的 pointer 與 allocation 原站本次回應 HTTP 503，因此沒有將這兩頁列為已讀。C 基礎正式撰寫前仍需補查可取用的 primary source，尤其 malloc／free、size_t／uint8_t 與 C string 的精確契約。

正式API重新核对std1.99的from_raw_parts_mut、pointer.add、Send／Sync、Reference UB／soundness與2024 unsafe_op_in_unsafe_fn。特別確認：
- from_raw_parts_mut即使長度零仍需要non-null與alignment；nonzero元素全部有效、同一allocation、總byte範圍與地址不overflow，整個回傳borrow期間保持獨占。
- pointer.add的非零位移要同一allocation／範圍；零位移不要求指向真實元素。因此空Vec的合法空slice可以沿其data pointer構造零長度結果，不能聲稱空slice一定配置了i32。
- public safe介面不能只靠「caller應該傳合理mid」免除作者檢查；safe client有權交任何usize。unsafe fn公開Safety契約與private欄位不變條件各有責任。
- Send／Sync是unsafe auto traits，raw pointer自身兩者皆沒有；本次只讀i32借用wrapper保存真實來源reference、private pointer，按其有限API單獨列移交／共享理由。不使用PhantomData或自行配置，沒有替Rc／Cell增加能力。
- 初步研究中的「所有safety錯誤只要看unsafe block」不可沿用；safe constructor的檢查與private欄位更新也可能破壞unsafe前提，必須一起審查。

### 正式契約與編譯指令的核對

下載並實讀 [WG14 C11 委員會草案 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) 的 5.1.2.2 main、6.2.4 storage duration、6.3.2.1 array conversion、6.3.2.3 pointer／void *、6.4.5 string literal、6.5.3.4 sizeof、6.5.6 pointer arithmetic、6.7.9 char array initialization、7.8.1 PRI format macros、7.20.1.1 exact-width integer types、7.21.6.1／3 formatted output、7.22.3 malloc／free、7.22 EXIT_SUCCESS／FAILURE、7.24.6.3 strlen。這是正式 C11 的委員會草案，不冒稱付費 final ISO publication。

- int32_t／uint8_t 是可選的 exact-width typedef；選用的 GCC host 提供它們，不將 int／size_t 的寬度當跨平臺固定值。sizeof 的 C byte 單位在此 host 是 8 bits。
- C object pointer 可與 void * 轉換，本節 malloc 的回傳在 C 可直接指派給 int32_t *。malloc 未初始化；成功 storage 對本節基本型別的 alignment 足夠。只配置固定三項，size 乘法不 overflow、不教零大小配置。
- free 接受 NULL，其他值必須是對應 allocator 的原始回傳值且未釋放；alias copy 不新增 owner、不能 free local array 或內部元素。free 之後不再讀取那些 pointer。
- pointer arithmetic 受同一 array 與 one-past 範圍限制；本節 len0 的 NULL helper 分支不做 dereference 或 pointer arithmetic，不能套用到要求 non-null 的 Rust from_raw_parts_mut。
- 字串 literal 的 storage 不可修改；`char word[] = "Rust"` 產生 mutable array 副本並包含末尾零。strlen／本節無 precision 的 `%s` 都需要有效的零結尾資料；一般 buffer 不因此取得 C string 資格。
- printf 的參數需對應 format conversion；`%zu` 配 size_t，int32_t 用 PRId32 和相鄰 literal 合併，不假定 `%d` 一定對應 int32_t。有限 demo 的輸出供觀察，不主張完整 I/O failure recovery。
- sum helper 的每次中間結果都須在 int32_t 範圍；C signed overflow 不能視為 Rust 的固定 debug panic 或 Python 大整數。本節不執行 overflow／越界／use-after-free 作證據。

實讀 [GCC Overall Options](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html) 的 -c／-o 與 compiler driver stages、[Standards](https://gcc.gnu.org/onlinedocs/gcc/Standards.html) 的 -std=c11／hosted、[Warning Options](https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html) 的 -Wall／-Wextra／-Werror／-pedantic。先教 compiler／object file／linker 分工再給完整 commands；warnings 與 successful compilation 都不能證明 C ownership／memory soundness。
