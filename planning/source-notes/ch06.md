## 官方語言與標準函式庫查核

### associated type、Fn 與 function pointer

- [Rust Reference：associated types](https://doc.rust-lang.org/reference/items/associated-items.html#associated-types)：實讀宣告、trait impl 的具體選擇、Self／型別參數的 associated type 路徑。6.2 先用有限的自訂介面教 `type Output`、`Self::Output`、`T::Output` 和 equality bound；同一個實作選出一個輸出型別，不是每次呼叫任選型別。GAT、Sized/?Sized、inherent associated type 等延伸不納入本節。
- [FnOnce](https://doc.rust-lang.org/std/ops/trait.FnOnce.html)、[FnMut](https://doc.rust-lang.org/std/ops/trait.FnMut.html)、[Fn](https://doc.rust-lang.org/std/ops/trait.Fn.html)：實讀每個呼叫接收自身值／mutable reference／shared reference 的角色、能力包含關係與 FnOnce 的 `Output`。6.3 用穩定 Rust 的 `Fn(i32) -> i32` 等形式教輸入／輸出，箭頭連回 associated Output；不直接使用文件列出的 nightly-only call_once/call_mut/call 方法或 extern rust-call。
- Fn 與 FnMut 的包含關係，是可用哪種 receiver 呼叫的介面能力；「move capture」與「呼叫時移出 non-Copy 值」須分開。保存 Copy 值或 reference 的 move closure 並不會自動變成僅 FnOnce。
- 後文 8.8 會教 interior mutability，因此本章不可把 Fn 說成所有可達底層資料永遠不變；目前例子的「不修改」結論限定到該例的值與操作。

### impl Trait 與 edition 2024 capture

- [Rust Reference：impl Trait](https://doc.rust-lang.org/reference/types/impl-trait.html)：實讀參數位置、回傳位置、單一具體回傳型別限制、generic capture 與 precise capture。參數位置讓呼叫者提供符合 trait 的具體型別；回傳位置由函式選擇單一具體型別，呼叫者只能使用公開的 bound。
- [Edition Guide：RPIT lifetime capture](https://doc.rust-lang.org/edition-guide/rust-2024/rpit-lifetime-capture.html)：實讀 capturing 定義、edition 2024 隱含 capture、use<...> 最小對照與 migration 說明。RPIT 是 return-position impl Trait，opaque 是隱藏具體型別的介面表示；capture 是隱藏型別允許依賴哪些泛型參數，與 closure 在執行期保存值的 capture 不同。
- 本專案 edition 2024：未指定 precise capture 時，回傳 opaque 型別捕捉 scope 內的泛型參數，包括 lifetime。這項依賴可以限制回傳值的使用範圍，即使本次隱藏實作沒有實際保存該 reference。
- 本節借用 helper 可用已教 Fn 與 reference，不需先展示 Iterator。先解釋回傳 closure 捕捉的 reference 與它借用的資料，才展示回傳 helper；如果範例引入 `use<'a>` 或 `use<>`，必須先教它的用途與具體選擇。無需在本章引入 `'static`、const generics、HRTB、Captures trick 或過時的 outlives trick。
- use<...> 不是 extend lifetime 的工具；其現行限制包括必須列入 scope 內所有型別／const 泛型參數，因此不展示暗示可任意忽略型別參數的例子。參數位置 impl Trait 的匿名型別參數與 precise capture 共用時有額外限制，本章 helper 避免把兩項混在同一個簽名。

### Iterator、IntoIterator、adaptor 與 collect

- [Iterator](https://doc.rust-lang.org/std/iter/trait.Iterator.html)：實讀 next 基本宣告，以及 map、filter、fold、collect 的簽名與行為。next 以 `&mut self` 推進狀態；Item 可以是值，也可以是 reference。for 在第一個 None 結束；一般 Iterator 不保證此後所有 next 永遠 None，自訂有限範例會自行保存結束狀態。
- [IntoIterator](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html)：實讀 `Item`、`IntoIter`、`IntoIter: Iterator<Item = Self::Item>` 與 into_iter 取得自身值的契約。它建立 iterator，Iterator 自身也可參與 for；collection、`&collection` 與 `&mut collection` 對應的具體 Item 不能含混成同一 ownership 行為。
- map callback 接收 Item，輸出新的 Item；filter callback 接收 `&Item`、回傳 bool、保留原 Item。從 shared slice.iter 取得 `Item = &i32` 時，filter 參數就是 `&&i32`。先顯式型別與 dereference 說明，再考慮 pattern 簡寫。
- fold 的 accumulator 與 Item 是兩個獨立角色，初值先確立 accumulator 型別；每次 callback 回傳下一個 accumulator，最後取得單一結果。有限材料的手動迴圈與 fold 應完成同一任務，不能只說 chain 比較快或原迴圈做不到。
- [FromIterator](https://doc.rust-lang.org/std/iter/trait.FromIterator.html)：實讀 trait 的集合建立角色、from_iter 與 collect 對照、自訂 collection 最小實作。collect 的回傳型別決定建構目標，Item 決定輸入元素。先由 `Vec<i32>` 明確型別，再回收 3.3 的 turbofish；從 `&i32` 收集不會自動變成 `Vec<i32>`，要選擇 owned iterator 或先顯式 map 取 Copy 值。
- [Result 的 FromIterator 實作](https://doc.rust-lang.org/std/result/enum.Result.html#impl-FromIterator%3CResult%3CA,+E%3E%3E-for-Result%3CV,+E%3E)：實讀成功收集與第一個 Err 短路，包含後續 callback 不再執行的觀察。成功值形成目標集合；遇到第一個 Err 就回傳，已取得的成功集合不會作為部分結果回傳。這不是把全部錯誤收集起來，也不是自動把 E 轉成其他錯誤型別。
- 本章若用 Result collect，可採自訂具體 enum 與已教 match，避免依賴尚未完成的 5.4／5.6；若要用 parse、FromStr、?，必須等待並引用第 5 章實際教法。

### 文字、HashMap entry 與排序

- [str::chars](https://doc.rust-lang.org/std/primitive.str.html#method.chars)、[str::lines](https://doc.rust-lang.org/std/primitive.str.html#method.lines)：實讀 Item 類型與分界契約。chars 的 Item 是 Unicode scalar 的 `char`，不等於顯示字形；lines 的 Item 是借自原文字的 `&str`，移除 LF 或 CRLF，最後一個行尾不多產生一行，空文字產生零行；單獨 CR 不當成行尾。
- [HashMap::iter / IntoIterator](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.iter)：實讀任意順序與 shared tuple／owned tuple 的差別。穩定輸出要明確收成清單並排序；不能把 hash iteration 的一次結果當成輸出順序契約。
- [Entry::or_insert_with / and_modify](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html)：實讀 Entry 占用／空位的動作與 FnOnce callback 契約。and_modify 僅處理已存在值，or_insert_with 僅在空位才呼叫提供預設值的 closure；回傳 mutable reference。6.7 先教借用整份 map 的 Entry 過程，再用回傳 reference 修改計數，不同時再次借用 map。
- [Ord](https://doc.rust-lang.org/std/cmp/trait.Ord.html)、[PartialOrd](https://doc.rust-lang.org/std/cmp/trait.PartialOrd.html)：實讀排序關係、Ordering、partial_cmp 可能無比較結果、與 PartialEq/Eq 的一致性。排序比較 closure 的回傳是 Ordering enum；不是 bool。數字／char／文字的標準順序要在第一次依賴前交代；字串順序不是本地語言的語意排序。
- [slice::sort_by / sort_by_key](https://doc.rust-lang.org/std/primitive.slice.html#method.sort_by)：實讀 FnMut 契約、保留相等項目原順序與比較一致性要求。callback 可能被呼叫多次，不能宣稱每個元素一次；本節用已教的 `as_mut_slice` 取得視圖後呼叫排序，直到 8.3 才採自動 Deref 簡寫。
