## 官方 API 查核

當下頁面版本為 Rust 1.99.0、Tokio 1.53.3、reqwest 0.13.5、axum 0.8.9。這是來源研究的版本觀察，尚不宣稱範例已編譯或鎖版。

| 11.1 | [IntoFuture](https://doc.rust-lang.org/std/future/trait.IntoFuture.html) | `.await` 會先轉成 future；`IntoFuture` 的 `Output`／`IntoFuture` associated types 與 `into_future` 角色。實作 Future 者也實作 IntoFuture。`Future<Output = T>` 是使用契約，本章不展示 poll／Pin 簽名。 |
| 11.2 | [JoinHandle](https://docs.rs/tokio/latest/tokio/task/struct.JoinHandle.html)、[JoinSet](https://docs.rs/tokio/latest/tokio/task/struct.JoinSet.html)、[AbortHandle](https://docs.rs/tokio/latest/tokio/task/struct.AbortHandle.html) | spawn 提交 task；JoinHandle await 得 `Result<T, JoinError>`，與工作自己的 `Result` 分層。丟掉 JoinHandle 會 detach；丟掉 JoinSet 會取消仍追蹤的 task。`abort` 是請求中止，`is_finished` 不會因呼叫 abort 立即變 true，最後仍要等待。已開始的 spawn_blocking 工作一般無法 abort，不能把此契約套到它。 |
| 11.2 → 11.5／15.9 | [JoinSet：join_next_with_id](https://docs.rs/tokio/latest/tokio/task/struct.JoinSet.html#method.join_next_with_id)、[AbortHandle：id](https://docs.rs/tokio/latest/tokio/task/struct.AbortHandle.html#method.id) | 若要把 panic／取消對應原輸入，先教 task `Id`；spawn 回傳的 AbortHandle.id 記成 Id→輸入 index。成功得 `(Id,T)`；失敗透過 JoinError.id。只在正常 Output 帶 index 會在 task panic／abort 時失去身分。Id 是追蹤期間的身分，不是永久不重用的應用程式序號。 |
| 11.3 | [JoinSet：len／join_next](https://docs.rs/tokio/latest/tokio/task/struct.JoinSet.html)、[Tokio mpsc 教材](https://tokio.rs/tokio/tutorial/channels) | 集合內至多 jobs 個 task；完成一個、收下結果後才補一個。join_next 是完成順序，不是輸入順序；空集合回 None。mpsc sender 可 clone；receiver 單一且需 mutable；容量滿時 send 等待，receiver 關閉時 send 回錯誤。 |
| 11.4 | [Tokio timeout](https://docs.rs/tokio/latest/tokio/time/fn.timeout.html) | `timeout(duration, work).await` 是 `Result<work_output, Elapsed>`；若 work 的 Output 又是 Result，就需分清兩層。包住完整取得 headers 工作才符合項目期限。timeout 不會中斷長時間不交還控制權的同步工作；此版文件標示先推進 future 再檢查期限，不能貼舊版相反敘述。timer 必須在啟用 time 的 runtime 內建立。 |
| 11.5 | [select!](https://docs.rs/tokio/latest/tokio/macro.select.html)、[JoinSet：abort_all／shutdown](https://docs.rs/tokio/latest/tokio/task/struct.JoinSet.html#method.abort_all) | 多分支在目前 task 內並行等待，並非每個分支建立 thread；一個匹配分支完成後丟棄其他 future。mpsc recv 與 JoinSet join_next／join_next_with_id cancellation safe；重建等待不會遺失已接收訊息／取走結果。全部分支停用且無 else 會 panic。abort_all 不清空集合，要持續 join 到 None；直接 shutdown 會忽略收尾 panic，B 報告若需保留分類應手動收集。 |

## 受控驗證的寫作決策

以下是作者後續的安排，不是已驗證範例，也不能交给首次閱讀者作提示。

1. 11.1 用無外部網路的最小工作看出「呼叫先得到 future，await 後才得到值」。在程式前教 `#[tokio::main]` 的展開角色、runtime／features；不用有 Pin 簽名的 Future 完整定義補洞。
2. 11.2 區分工作錯誤與 task failure，逐步教 JoinHandle／JoinSet／task Id。能以受控 channel 卡住工作，再發訊息讓它完成，不需靠 sleep 猜 task 已啟動。
3. 11.3 用開始／允許完成的事件證明至多 jobs 個工作，而不是只量整體秒數。控制訊息的容量、send／recv 與所有 sender 的 ownership 必須先交代。
4. 11.4 timeout 可包住沒有放行的 channel 等待，以不同可控制操作呈現正常／逾時兩類，不把 CPU busy loop 當可被強制中止。Duration 的單位、Instant 的時間點／elapsed 與 deadline 範圍在使用前教。
5. 11.5 每次等待只用 cancellation safe 的接收與取結果；收到 stop 後停止補新工作，abort_all 後完整 join；保留已完成結果，不把所有仍在集合的 task 一律覆寫取消。正常輸出、task failure、取消／未開始有不同身分与後續用途。
6. 11.8 先從最小回應服務增加狀態、redirect、受控延遲與計數，每次只加一個主要需求。動態 port 的 listener 取得成功是 listener readiness；如果需要 HTTP handler 已能回應，用真正健康回應或事件確認，不靠固定 sleep。
7. 本機 fixture client 要在程式前教 `ClientBuilder::no_proxy()`，避免執行環境代理改變測試對象；一般使用者 client 繼續尊重環境代理。這是 fixture 路徑的具體必要差異，不要求教整套 proxy 配置。
8. 受控延遲 endpoint 若還等 release gate，graceful shutdown 會等尚在服務的 handler；fixture 收尾需先釋放 gate 或明確另行取消並等待，不能只 send stop 後宣稱立即收尾。
9. B 專案後來會以 input index 排序；本章先教 task完成順序與 task Id，再教輸入身分 mapping，保證 task failure 也可對回原項目。
