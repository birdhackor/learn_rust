# 300 — 最小完整本機 HTTP 與 server 收尾

完整no-libmanifest/main、命令與兩行預期全讀；無PNG，沒有實際bind/GET/跑程式。這是本教材source首次真正使用client/server的整合，不能把「source做真HTTP」說成我已實跑。

1. **what（explained）**：basic只有本地welcome/Router/service，非尚未教的Fixture；axum0.8.9開http1/tokio、Tokio rt/macros/net/time/sync，client用295完成library。GET/ok→200與Rust本機服務body，最後有停止和server結果。
2a. **機制／性質（explained）**：持bind同listener，localaddr格式http://addr/ok，stopchannel的asyncmove等recv後回unit，交graceful。service.into_future再spawn；mainawaitinspect true，先存Result，再送stop存notification、server.await存finished，**之後**才expect/assertreport及檢兩層finished。這條順序不因client檢查失敗提前丟server等待handle。currentthread中servertask/client等待由runtime推，不必另OSthread，也未證parallel。
2b. **why（explained）**：從人工報告轉真送HTTP，並讓本機服務有可驗的有限結尾；所得status/body與整server工作已完是不同證據，不能啟完就依賴外部kill。
3. **how（explained）**：clientdirecttrue避免proxy、limit10；RouterGETwelcome，ownedlistener移service；inspect借client、接Url、讀body。stop.recv的Option值雖忽略，blockOutputunit符合299；serverawait須Ok(Okunit)，innerioErr與outerJoinErr分別panic文案。
4. **例子界線（explained）**：此welcome立即回，沒有受控gate/entered通知，還未驗request逾時、body失敗、服務阻在handler等場景。兩行stdout是教材預期，不是我的terminal；無指定port／elapsed、沒有TLS測試。

小預測：若只故意把report.body的expected文字改錯，assert會失敗但之前已server.await；不能沿該失敗就說server還未被收尾。若只建Router不spawnservice，則沒有此程式給出的完整HTTP/結束流程證據。依已教流程小變化，未改／未跑。

後釐清：297/298/299未給完整監聽、轉Future、停止順序現在一份source接齊；深層TCP/HTTPbytes由library處理，不假稱已學自造協定。
