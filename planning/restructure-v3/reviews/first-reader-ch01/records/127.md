# 第4章逐段首讀 127

範圍：feed127 guard、or範圍、完整成功／E0004失敗碼；此前000–126。未跑教學。

## guard先配形狀再算bool：已解釋

引用：「pattern後、=>前」「兩項都成功」「false…後面的arm」。

1. 關係：補126無法用名稱pattern比較外部門檻的需求；guard是bool expression，不是把比較塞成新binding。
2a. Amount先綁amount，guard用它和外minimum比較，成功才做右expression；不符則繼續配後arm。2b. 用途：同形態內依執行時資料再篩選，既保留數字又讀外門檻。
3. Amount(120),100→120；Amount(80),100先配形狀但guard false，進Amount(_)=>0；Missing=>0。
4. 不把guard當另一次函式呼叫或先於pattern計算，也不以它改變新binding的scope規則；本例沒有複雜ownership效果。

## guard涵蓋整個or pattern：已明述

引用：「整個or pattern」「不是只有…2才檢查」。

1. 關係：124學or、現在附加共同條件，不能誤讀成1無條件或只有2有ready要求。
2a. 1或2都須ready true，否則_0；2b. 用途：共用arm時條件也共同適用，精確表示兩件事都必要。
3. 1|2 if ready=>count，count／ready為函式原參數，literal patterns不建立新count。原例1,false→0；2,true→2。
4. 不依符號外觀套bool expression的優先序，也未教所有更複雜or／guard寫法。

## guard不負責exhaustive覆蓋：已解釋

引用：「不把帶guard的Amount當成…所有」「安排後續arm」。

1. 關係：114要求合法型別全涵蓋；形狀可能配上卻guard false，仍需出口。
2a. 只列Amount if >=0與Missing缺少不過條件的Amount，E0004；2b. 用途：不能因目前呼叫120通過就把所有金額當已處理。
3. 成功例用無guard Amount(_)作後續0結果，才有各Amount路徑；此0有本函式貢獻規則。
4. 例子不教授編譯器證明任意bool的能力或所有分析算法；只能依已明說帶guard不算完整形態覆蓋，不擅假設guard永遠true即可省arm。

自己的預測：contribution(Amount(80),80)回80，顯示門檻真的可由呼叫者改；selected_count(1,true)=1、(2,false)=0、(3,true)=0。若把無guard Amount(_)移最前，所有金額先回0，120也不再過guard那個arm，雖然仍涵蓋完整。

123第三需求及124保留的or／guard作用範圍現在有明確規則，不回改舊判斷。所有必要完整source已讀；無圖。
