## Build script 與四階段

1. **角色（explained）**：原文「在建置時決定，再把文字固定進成品」；build script是Cargo先執行的一支Rust程式，通常package根build.rs，不是成品每次啟動的main。沿220的host/target，script為host編譯執行。
2a. **機制（explained）**：先編譯script、執行script成功，再編譯主要crate，最後執行成品。manifest build="build.rs"相對package根，慣用名可自動發現。Cargo可沿用結果，不承諾每次命令重跑。
2b. **用途（explained）**：保存demo/practice建置識別，使runtime外部環境不能悄悄改寫這次成品的模式。
3. **用法（explained）**：本次換到repo根workspace ch09-build-script，不沿上頁小workspace。build.rs讀LESSON_MODE，交付TEACHING_MODE，lib的build_mode回固定文字，main顯示。
4. **實圖／界線（explained）**：PNG四個垂直框：1編譯build.rs供host執行→2執行script讀LESSON_MODE／交付TEACHING_MODE→3編譯主要crate由env!固定文字→4執行成品不重讀模式；箭頭只表先後，不是所有權箭頭、資料地址或每次重跑保證。

小預測：在practice成品直接啟動時把LESSON_MODE改wrong，也不會重新做本頁script的拒絕驗證；它仍報practice，除非主要程式另外讀runtime環境。未跑。

## env::var 與 host／target 資料

1. **角色（explained）**：`env::var` 是目前行程runtime讀環境的Result<String,VarError>，這裡目前行程是script。NotPresent缺值，NotUnicode(OsString)存在但不是可轉String值，沿既讀原生字串差異。
2a. **機制（explained）**：缺LESSON_MODE預設demo；其他文字只准demo/practice，非Unicode拒絕。Cargo啟動script會提供CARGO_CFG_TARGET_OS，所以這個expect有教材明列的保證；script的cfg!(target_os=...)卻查script自身host，不是主要crate target。
2b. **用途（explained）**：不把錯誤資料當未設定；交付正確的主要目標資料，跨平台時避免host/target碰巧相同造成誤解。
3. **用法（explained）**：先match var，再驗證as_str；target_os由Cargo資料取，host_windows由cfg!取，再轉成輸出文字。TEACHING_HOST_WINDOWS保存的是true/false文字，lib不解析bool。Bash NAME=value command只交這次命令及子行程。
4. **例子界線（explained）**：教材Linux兩者linux/false不是所有平台保證；沒有實作跨編譯，也沒給NotUnicode環境的生成操作。任意外部字串在驗證前不直接印入多行協定。

小預測：取消LESSON_MODE和給空字串不同：取消走demo，空字串是存在的非法文字；未跑。script的target_os文字可windows而host_windows=false，依已讀跨平台角色推論而非實例。

## stdout 建置協定與追蹤

1. **角色（explained）**：原文說Cargo依stdout每行「建置協定」接設定，不用main回傳值當設定；cargo::形式是本工具鏈支持的格式。
2a. **機制（explained）**：rerun-if-changed=build.rs縮小檔案追蹤；rerun-if-env-changed=LESSON_MODE追使用者交Cargo的配置含設定／取消，不能拿來追Cargo自己的TARGET資料。rustc-env交下一階段編譯環境；cargo::error令script結束後建置失敗，即使script main回unit。-vv可看通常不直接顯示的script細節。
2b. **用途（explained）**：輸入變化時更新固定模式，輸入無變可重用；將建置失敗定位在編譯前，不等成品啟動。
3. **用法（explained）**：完整script先列追蹤行，錯誤println cargo::error後return，合法才印三個rustc-env。wrong cargo check預期失敗，不需刪target再改demo。
4. **例子界線（explained）**：正文提供協定契約和兩次cargo run預期，未實際觀察快取或Cargo詳細輸出；return本身不是失敗碼，真正讓Cargo拒絕的是error協定。

小預測：只把runtime成品的環境改值，不經Cargo，不會觸發rerun追蹤；LESSON_MODE設定變取消則屬追蹤範圍。未跑。

## env!、option_env! 與編譯期文字

1. **角色（explained）**：env!編譯期取&'static str，缺值／非Unicode編譯失敗；option_env!編譯期取Option<&'static str>，只有缺值是None，非Unicode仍錯。沿先前env! binary path和static文字，不是env::var每次呼叫。
2a. **機制（explained）**：rustc-env給的三字串在lib編譯時嵌入；普通函式返回該static文字。source中env!/option_env!讀的值也被Cargo/編譯器追蹤，不需build.rs重讀一次。CARGO_PKG_NAME由Cargo自動給編譯package crate。
2b. **用途（explained）**：必要模式失去就拒絕編譯，可省略額外tag用None明確表達；build_identity可組package/mode/target而保存建置識別。
3. **用法（explained）**：missing_env fixture讀刻意未給值，診斷not defined at compile time；optional tag無值印沒有，有lab則印lab，直接已編譯example保留那次tag。答案format!組成String再顯示。
4. **例子界線（explained）**：fixture失敗時還沒有main能跑。integration tests只確認允許模式及Linux/Windows的target文字，不測跨平台工具；兩份example及完整答案都已讀，不稱未提示自行解出。

小預測：option_env!有Some(空字串)不會變None，因為存在／缺少和文字內容不同；若要額外限制tag，還需自己政策，此頁沒加。未跑。

## OUT_DIR、build-dependencies 與 linker 預告

1. **角色（explained／deferred）**：OUT_DIR是Cargo給script的本次生成輸出目錄；build-dependencies供host script，dependencies供主要crate。linker將編譯結果和所需library組成成品；這頁只給後續整合的角色預告。
2a. **機制（explained）**：OUT_DIR可能有前次檔案，script自行管理要重建的內容，不寫回原source目錄。兩種依賴各明確宣告。rustc-link-search=native=路徑加搜尋處，rustc-link-lib=static=名稱要求靜態library納入所需程式。
2b. **用途（explained）**：保持輸入與建置輸出分工，分開host工具和target成品library。link指令只交設定，不能代替取得library、平台相容性或外部函式／ABI契約。
3. **用法（有限 explained）**：此script只交文字，沒有生成檔、讀生成檔macro、build-dependency或link行；不需要C工具鏈。實際原生整合明說第15章，未讀也不追查。
4. **例子界線（deferred when not needed）**：沒有一個可操作的原生library範例，所以只理解兩條協定用途，尚不能宣稱能完成整合；這是明列預告，現在執行本頁不需要它。

小預測：在dependencies加入library不等於script自動可用它，仍需build-dependencies；此為兩表明說責任推論，未跑。
