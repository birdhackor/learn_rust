## tokio::sync::mpsc 的可 await bounded channel

1. **what（explained）**：同mpsc多送單收用途，但這是Tokio同步工具，manifest加syncfeature。channel<T>(capacity)回Sender/Receiver且capacity>0，不沿std容量0rendezvous規則。
2a. **機制／性質（explained到介面）**：Sender clone共channel；send(value).await等空位，Okunit或關收端帶原值SendError；recv().await要mutable借Receiver，Someownedvalue、暫空且有送端則等、全送端結束且空則None。與std recv Result／sharedreceiver不同。await等待時如何被喚回仍未說，不拿API用途充底層機制。
2b. **why（explained）**：在async工作中以通知條件等待及續進，不用blockingstd收取或猜毫秒。此處目的依正文是分開始和放行。
3. **how（explained）**：型別可unit，mut release Receiver使.recv可呼；syncfeature加在已rt/macros上。Sender失敗保原值和既讀錯誤owner概念相連，但本包沒展示取SendError欄位或所有traitbounds，不代入std的精確型別能力。
4. **例子界線（explained）**：本包只是worklib，controller尚未出現；可讀接口但還不能跑完整互動。capacity必正數是明示要求，未給違反診斷，不自行猜panic字串。

小預測：即使buffer暫空，只要release送端仍活著，recv不會自行None，工作仍等；drop全部送端且空才ControlClosed。未跑。

## started 與 release 是兩種獨立進度證據

1. **what（explained）**：兩條channel用()通知；work持startedSender讓controller知body到送通知；controller持releaseSender讓work獲准繼續，非傳庫存或金額。
2a. **機制／性質（explained）**：controlledwork先started.sendawait/expect，drop自己的started；再release.recvawait，Someunit通過，None提前returnErr。release不送且sender在就不能越過，started收到只證到送出那點，不能證結果完成。
2b. **why（explained）**：提交task不能保某行已執行，用工作自己通知建立進度依據；再由獨立release控制下一段，避免時間猜測。
3. **how（explained）**：controller需持started收端到收妥才符合expect前提；work保mutrelease receiver。收到Some才走panic_after_release和amount檢查。還未見controller完整main，保留待下包。
4. **例子界線（explained）**：unit沒有附加資訊，不代表一份通知能同時回金額或所有清理都完；dropstarted不使release自動放行。

小預測：只收started卻不送release，不能沿原lib算出成功；若controller drop release送端，work收到None而非等待指定時間。未跑。

## WorkError Output 與放行後順序

1. **what（explained）**：Output=Result<i32,WorkError>，Negative(amount)拒負小計，ControlClosed為放行前所有release送端已終止；二者正常return，panic_after_release為另指定失敗，具體taskErr待教。
2a. **機制／性質（explained）**：releaseNone最先return；Some後先判panicflag再amount<0，再Ok(amount)。本lib**回原amount**，沒有14.2加20，不把80自動算100。
2b. **why（explained）**：把業務拒絕／控制通道關閉的正常結果與真正panic分別，供後續等待結果檢查。
3. **how（explained）**：amount80、false、Some通知可回Ok80；負數false回Negative；flagtrue且已放行才panic。startedexpect失敗也可panic，但本例有controller持收端的前提。
4. **例子界線（explained）**：本包沒展示task handle的Err型別或測試執行，所以只可讀body結果，不說panic如何跨回controller。

小預測：即使panicflagtrue或amount負，release若先None仍ControlClosed，因早return在它們之前；送Some且flagtrue時則不走Negative。依實際source小變化，未跑。
