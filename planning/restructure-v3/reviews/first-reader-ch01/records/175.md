# 175：TextView的lifetime欄位（staged初判，含必要圖）

## 概念一：struct宣告lifetime parameter

引文：「欄位的來源要求要跟著型別走」、「`pub struct TextView<'a> { pub text: &'a str, }`」。

- **Q1：已解釋。** 174借用模型的具體型別，用'a描述text來源有效關係，非新資料型別。泛型參數位置像150 Holder<T>，現在是借用範圍參數。
- **Q2a：已解釋此宣告。** TextView名字後先宣告<'a>，欄位&'a str使用它；pub型別與pub欄位各自控制公開，非只開一個就全開。
- **Q2b：用途已解釋。** 把欄位的來源要求跟模型型別一起表達，因模型不能憑空保證外部文字有效。
- **Q3：當前定義已懂，caller尚未展示。** 可定義此reference欄位模型；由既有struct與as_str規則，我料想可把source.as_str放text（合理推論），但此包沒有完整建立程式或方法，尚未看到型別位置的`'_`。
- **Q4：程式及圖界線。** 只有型別和角色圖，未展示view方法借用、如何交回欄位或具體scope成功／失敗程式，不能將'a直接解作模型變數的整段scope。

## 概念二：模型持有reference值，文字owner仍在外部

引文：「沒有取得被借文字的ownership」、「將reference放進struct，不會讓原String多活一段時間」。

- **Q1：已解釋。** 把借用包進struct不改文字責任，與String欄位擁有文字不同；174的owner有效推論現在有明文支持。
- **Q2a：已解釋。** view.text是模型欄位中的reference，source管理文字；還要經模型用欄位時，source必須有效，非把文字另複製進view。
- **Q2b：用途已解釋。** 需求只要既有視圖，所以可保留外部owner，而模型攜帶借讀入口和來源要求。
- **Q3：當前資料關係已懂。** 原資料由source:String提供，view提供text:&'a str讀它；沒有新的owned文字輸出。
- **Q4：親看圖片所得。** 已view當包`figures/ch07-borrowed-field.png`：上藍框view:TextView<'a>，欄位view.text:&'a str；藍箭頭向下指綠框source:String「仍是owner」，管理Rust tutorial。箭頭旁明寫借原文字／沒有另建一份內容；下框說借用使用時來源須有效。圖不是ownership轉移箭頭，沒有時間軸，也沒顯示source何時清理。
