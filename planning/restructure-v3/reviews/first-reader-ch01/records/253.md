## JoinSet 與 AbortHandle

1. **what（explained）**：JoinSet<T>持一組Output同T的tasks，new空集合；tasks.spawn提交並納入，回AbortHandle，不是249單份JoinHandle。
2a. **機制／性質（explained到契約）**：AbortHandle可id或請求abort，結果從集合收，不用它await。各task可不同成功／錯誤，但Output外形同Result<i32,WorkError>。AbortHandle自己Drop有何效果未說，不把JoinHandle detach規則硬套。
2b. **why（explained）**：多份工作完成後由同集合逐份取回，用回傳控制權限辨工作，但不每份另用JoinHandle等結果。
3. **how（explained當前片段）**：tasks是&mutJoinSet<Result<i32,WorkError>>，spawn時另記Id→input，collector從集合回收；完整四筆spawn還沒出現。
4. **例子界線（explained）**：目前helper不是整個四筆示範，不憑標題猜完成順序；沒說Set能裝任意不同Output型別。

小預測：若一task Output i32、另一OutputString，不能單憑兩者都是future就放進同一個T集合；需相同Output介面，具體轉型設計未教。未跑。

## join_next_with_id 的 Option／Result

1. **what（explained）**：mut借set、await等一已完task並取出，回Option<Result<(Id,T),JoinError>>；空集合None，尚有工作沒完成則等，非None。
2a. **機制／性質（explained）**：成功tuple id+整Output；taskErr透error.id取id。收回非input順序，多個已完也不推按提交順。collect_one先拆Option，再外taskResult，內工作Result。
2b. **why（explained）**：可隨完成回報又保持空／仍未完差異；panic／取消沒有正常Output仍能辨是哪task。
3. **how（explained）**：None直接returnNone；Ok(id,Okvalue)→Value；Ok(id,Errwork)→WorkError；Err取id後查iscancelled/ispanic/其他.to_string。
4. **例子界線（explained）**：一call只收一份，不因set非空而立刻全交；本包尚未給受控四份完成材料，不能聲稱看過各類實際輸出。

小預測：若集合有一尚待release的task、其餘已收完，下次join_next不能像空集合立刻None；應等那份結束。未跑。

## Id 對照與 HashMap::remove

1. **what（explained）**：HashMap<Id,usize>是task身分→原輸入位置，不以taskId數值當index。remove(&id) mut借map刪組並交Option<usize>，是新選用的map方法。
2a. **機制／性質（explained）**：Some交已移出的position，None無鍵；collector每回收依id remove，expect依「每spawn都先登記」內部約定。最後map應空，不留下已收工作的項。
2b. **why（explained）**：完成順序和原input不必相同，連panic／cancel仍可用Id連回輸入，同時追蹤哪些未回收。
3. **how（explained）**：取得(id,outcome)後remove id→input，回SomeReport{input,outcome}。spawn登記細節待下一份完整source，不自行填假Id。
4. **例子界線（explained）**：helper相信caller遵約，不是map可自行恢復忘登記的input；若None會expectpanic。不能從Id直接推原位置。

小預測：有登記的id被remove一次後，再查同key應無項；但集合正常不該同task重回一次，對照清空是收尾條件。依remove契約推論未跑。

## Outcome／Report 報表政策

1. **what（explained）**：自訂Outcome Value/WorkError/Panic/Cancelled/OtherTaskFailure，Report加usizeinput；非標準庫所有Err合一分類。
2a. **機制／性質（explained）**：按兩層Result和JoinError查詢作enum分支；Other保.to_string訊息，不假裝知道其具體原因。Debug/PartialEq沿既讀derive。
2b. **why（explained）**：回報每輸入的結果與失敗種類，保business正常Err和task沒Output的差別。
3. **how（explained）**：collect_one→Option<Report>，None只說set空；WorkError內原原因留住，Panic只分類不在本包解payload。
4. **例子界線（explained）**：報表選不保panic文字是這份政策，不能推JoinError原來沒訊息或所有可能錯誤都只四種。

小預測：Negative(-1)即使金額不合法仍走WorkError，不走Panic；因它是Ok外層回正常Output。未跑。
