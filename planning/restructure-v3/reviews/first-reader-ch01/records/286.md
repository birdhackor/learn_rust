# 286 — AppError 階段、退出狀態與完整輸出

完整error.rs及render/run兩函式全讀；無PNG、未執行。Write／flush沿已讀10章，這包首次看本工具完整錯誤enum和輸出契約。

## AppError::status 不等 HTTP status

1. **what（explained）**：AppError存Url/Scheme/Client/Request/Body(status,error)/OutputIO。其自訂status()->u8是**退出數字**，Url/Scheme2、操作失敗1；Response.StatusCode的HTTP數字是別資料。
2a. **機制／性質（explained）**：Display保各階段，Request／Body各查reqwestError.is_timeout，Body文案保已收HTTPstatus，不把timeout統一說沒response。Errorenum有Debug，Display完整；此處沒宣告stdError trait，不需要替Result自動補這一條（沿215ResultE不必Error）。
2b. **why（explained）**：caller可用輸入／操作退出政策，人讀診斷又知道取得response前／body後哪步錯。不能混HTTP404、passedfalse、process退出值。
3. **how（explained）**：parseHttpURL的兩Err變體現在有定義；build/send/text分別包其reqwestError，Output包ioError。AppError.status供main後用，完整main未見，不猜Ok(false)怎轉退出碼。
4. **例子界線（explained）**：Display文字是source政策，未由實際錯誤生成測過；is_timeout分支不改原Body/request階段，也沒加進未教錯誤種類。

小預測：HTTP404且正常讀取不是AppError.status()=404，因它根本是Inspection／runOkfalse；若已收404而body讀錯才Body{status404,...}，AppError退出數字仍1。依285+本包分層推論未跑。

## render／run 的 writer 與成功邊界

1. **what（explained）**：render泛型Write，寫finalURL/status/passed，可選body，最後flush，回ioResultunit。run先inspect，render完整成功後才回passed bool；404=Okfalse非連線Err。
2a. **機制／性質（explained）**：每writeln?可早回錯，flush最後也可錯；run顯式包Output。成功HTTP不遮輸出失敗，部分已寫內容不自動rollback（沿203Write性質合理推論）。bodyNone不印段，Some即使空也進iflet。
2b. **why（explained）**：「拿到報告」與「已交出完整輸出」仍不同，需把writer/flush失敗報回；同時保未讀body和已讀空正文的差別。
3. **how（explained）**：&Inspection只借資料，&mutW接bytes；逐欄writeln，body段標body:後換行，flush。runW只在renderOk才Ok(inspection.passed)，否則ErrOutput。
4. **例子界線（explained）**：無實際Writer fixture在此包，不假稱已見失敗測試；flush是IO交付契約，不推出磁碟持久化或接收者已處理。HTTPstatus與writer錯誤不同域。

在取下一包前的小預測：若writer把所有文字寫完但flush回Err，run也應OutputErr，不能沿2xx報Oktrue；若Inspection.body=Some空String，仍會印body標記／空內容，None則省略整段。依實際code與舊Write規則推論，未跑。
