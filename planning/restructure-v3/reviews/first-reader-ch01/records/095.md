## 新example／自己的測試如何接既有library：可由已讀規則重建

引用：「use…三個公開函式，不複製」「範例自己的tests module」「預期值…規格」。

1. 關係：沿090的外部example模式，但main使用三項公開功能；nested tests仍須自己引入library名的路徑。
2a. 機制：Cargo用my_report檔名選binary／test target；cfg(test)只在測試建置加入，#[test]讓runner找出函式。2b. 用途：另一個呼叫者保存同一計價規則與預期，不重寫算法，也不從目前顯示反推規則。
3. 輸入輸出：main應顯示280、300、400；邊界300→300、空單0、兩組加總400／0。run走main，test選這個example的標記函式。
4. 題目沒規定測試函式數／名稱，以下4個是我自己的分組；不預先聲稱作者答案也這樣寫，亦不以紙上重建宣稱實際通過。

## 我的必要語法重建與預測（讀答案之前保存）

```rust
use intro_control::pricing::subtotal;
use intro_control::pricing::sum_three;
use intro_control::pricing::total_with_shipping;

fn main() {
    let goods = subtotal(140, 2);
    let total = total_with_shipping(140, 2);
    let sum = sum_three([120, 80, 200]);
    println!("商品小計={goods}，含運總額={total}，價目總和={sum}");
}

#[cfg(test)]
mod tests {
    use intro_control::pricing::subtotal;
    use intro_control::pricing::sum_three;
    use intro_control::pricing::total_with_shipping;

    #[test]
    fn report_order() {
        assert_eq!(subtotal(140, 2), 280);
        assert_eq!(total_with_shipping(140, 2), 300);
    }

    #[test]
    fn threshold_order() {
        assert_eq!(total_with_shipping(300, 1), 300);
    }

    #[test]
    fn empty_order() {
        assert_eq!(total_with_shipping(120, 0), 0);
    }

    #[test]
    fn both_arrays() {
        assert_eq!(sum_three([120, 80, 200]), 400);
        assert_eq!(sum_three([0, -5, 5]), 0);
    }
}
```

我預測這份自選結構若執行，上面run一行三數、test有4個test函式；assertion的總數不是測試數。若只把main的140改150而測試輸入不改，main小計變300，total仍300，但tests仍核對自己的140訂單，兩者不會自動同步。這是已學呼叫材料獨立性的變化。
