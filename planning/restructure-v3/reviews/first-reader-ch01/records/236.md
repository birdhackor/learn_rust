# 236 — 同時執行與安排比較圖

已實際view當包 `ch14-waiting-arrangements.png`，未執行。parallelism並非新名詞，這裡記本例所需條件。

1. **what（explained）**：parallelism是真正同刻多工作執行；本包另加A回覆已到、B未完和兩可用執行資源，才談同時處理A回覆與B計算。沿13.1原定義，不把async本身當多核心。
2a. **機制／性質（explained）**：兩thread若實際在不同CPUcore同時跑可以支持，但只建兩thread或畫兩欄不證當次真同時。倉庫自己工作不等我們程式同時跑兩段Rust。
2b. **why（explained）**：辨清等待期間交錯推進與同刻執行；不以圖形布局或建立工作代證資源真正使用。
3. **how（情境explained）**：資源1處理已到A，資源2完成尚未完B；完整report仍收3和200，不能消除依賴。沒有新操作API。
4. **圖實見（explained）**：頂固定A查庫存3、B80+120=200。橘①發A留等→收3→算B→完整報告；綠②發A尚未完→先B200仍等→收A3完整；藍③明寫「假設A已回，B尚未完成」，分資源1/2且粗體「此處假設兩段真的同時執行」。底箭頭操作先後／框高非耗時。①②箭頭不代表速度，③是加假設不是測量。

小預測：只有一條此刻在跑的執行資源，仍可能按②concurrency完成，卻不能單憑兩任務叫③parallel；若B依A，兩資源也不先得B答案。未跑。
