# 292 — elapsed_ms 的測量範圍

完整Inspection片段與正文已讀；無PNG／執行。

1. **what（explained）**：新增elapsed_ms:u128保存非負總毫秒。u128名稱我依已教u8/u64系列推為無號128bit（本包未列範圍，不作超界計算）；用途是本次檢查觀察值非固定標籤。
2a. **機制／性質（explained）**：stdInstant從準備GET前開始，建Inspection前結束；read_body時含它等待。parseURL/buildclient/writer輸出排除，非Tokio虛擬clock。沿264測量含該段本地進度和排程，不能說純網路耗時。
2b. **why（reasonable inference）**：讓報告給出有明確範圍的這次經過時間，非藉async名詞宣稱速度；依字段與明列範圍理解此用途，不替作者造效能需求。
3. **how（資料explained、code待見）**：其他Inspectionowned欄位不變，成功報告時附計時數；現只定義範圍未見start/elapsed實際行，下一完整source再核對。先前264未給as_millis回傳型別，這裡只確定保存型別u128，不強稱前包已知。
4. **例子界線（explained）**：後面人工12ms只驗格式，不代表有HTTP或真12ms；不能寫死實際elapsed，也不能用它當完整CLI總時間。

小預測：若writer.flush很慢，工具總耗時增加但依此範圍不加到已生成elapsed_ms；若讀body選項打開，則那段等待應包含。依已教範圍小變化，未跑。
