## 發現

### C2-01：return 的既有操作解釋應放在第一次程式使用前（必要；增加理解負擔；信心中等）

- 首次使用：`02-02-lesson.md:33–35` 的 `early-return` 片段，實際 `control-steps/examples/conditions.rs:3–5`：`if count == 0 { return 0; }`。
- 原文在片段前說：「數量為零時，答案已經是零，不必再計算商品小計或運費。把這一段放在計價函式開頭」。小節標題也已說 return 提早結束目前函式。這些已交代用途，不應報成缺少動機。
- 片段之後 :37 才具體說：「`return 0;` 立刻結束**這次函式呼叫**，把 0 交回呼叫者；函式後面的工作不再執行。它和函式尾端 expression 都能交出結果，差別是 `return` 能在中途離開。」:39 再說不是只離開 if block。
- 實際前文：1.6:7–17 已教回傳型別與函式 block 尾端 expression；2.2:9–19 已教 if 分支與 block 值。尚未在正文教過 Rust `return 值;` 的寫法。基本 Python 背景可能讓讀者猜對，但本輪要求 Rust 新用法先解釋、再放進程式。
- 最小缺口與影響：初次讀程式時，精確的「這個值交給呼叫者，整次呼叫停止」操作才由下文補足。這是局部解釋位置，不是完整單位結束後仍不懂 return；也不要求提前教控制流程內部實作。
- 建議：把 :37 的既有解釋移到 early-return 片段前；:39 對無 else 的解讀仍留在片段後。篇幅不增加。
- 實際頁面：`desktop-return-section.png`、`mobile-return-section.png`，兩種尺寸都確認先程式、後操作解釋。未修、未複查新版。

### C2-02：擴大工具 target 範圍時先讀到後面才教的 allow（必要；增加理解負擔；信心高）

- 已明確確認的首次載入位置：初始 `02-07-lesson.md:74–77`：
  - 「`--all-targets` 要求涵蓋這個 package 的 library、binary、範例與測試等 target……此處選的是內容都已教過的 `intro-control`。」
  - `cargo clippy --manifest-path examples/intro-workspace/Cargo.toml -p intro-control --all-targets --locked`
- 實際被納入的範例 `control/examples/lint_return.rs:2` 已有 `#[allow(clippy::needless_return)]`。其完整來源在 :93 才展示；具名 lint 於 :86 介紹，allow 的角色、作用範圍與保留理由於 :88 才解釋。
- 實際前文：:21–27 已教 attribute 外框、`#[test]` 與 `#[cfg(test)]`，:72 已教 lint 的一般角色。這不等於已教 allow 或特定 lint 名稱；也不能把後面的完整例子回算成 :77 當時已教過。
- 最小缺口與影響：指令本身可正常執行，但「實際載入的範例只用此刻已教能力」與「內容都已教過」的主張，在這個位置不成立。這是本輪操作／範圍邊界的問題，不是聲稱 Clippy 結果錯誤，也不要求 attribute 的完整內部機制。
- :66–67 還有 package 層級 fmt；本初判未以執行驗證 fmt 的所有實際 target 遍歷，故以明寫 `--all-targets` 的 Clippy 作已確證依據，不把未知的更早工具載入算通過。
- 建議：在 allow 說明與完整範例之前，工具先明確只選已教的 library；讀過具名 allow 與全部 target source 後，再擴大範圍。或把整體 package 檢查留到 2.8 全部來源之後。
- 實際頁面：`desktop-clippy-all-targets.png`、`mobile-clippy-all-targets.png` 保存初始命令／說明在前、allow 說明在後的位置。原觀察保留；封存末偵測到的新來源另記修後複查，不改寫此項。

- 原位置：`02-04-lesson.md:17–26`，五欄為檢查前 remaining、條件、processed、更新後 remaining、batches。表後明說「最後一列只檢查，沒有再多算一批」。

- 已足夠部分：表可橫向捲動，資料沒有遺失；程式、表後解讀與完整輸出也能推出7項是3批、最後 false 不增加批次。因此不列必要概念阻礙。
- 具體收益／最小改善：手機若能同時看到一列的前後剩餘量及批次數，讀者更容易確認最後 false 為何仍是3批。可縮短表頭、把變數對應放在相鄰圖說，或調整這一表的窄屏呈現；無須另加一套圖或新算例。不建議為此改動所有程式碼區塊的橫向捲動規則。
- 未修、未做修後複查。
