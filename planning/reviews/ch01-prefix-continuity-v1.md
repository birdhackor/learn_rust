### N2：workspace 兩段設定的新角色與繼承語法先展示後教

- 原位置：`docs/chapters/01-03-workspace.md`「根設定與成員設定如何配合」；凍結 `003-004.md:7–18`／`:28–36` 是設定，`:20–24`／`:38` 才補角色。
- 短引文：程式先含 `resolver = "3"`、`rust-version = "1.99"`、`publish = false`；成員程式先含 `edition.workspace = true`，其後才解釋「這個成員的 edition 使用 workspace.package 裡的共同值」。
- 已教部分：workspace 是多個 package、共用設定；TOML 通用語法與前節 version／edition；節錄不可覆蓋真設定的限制。`members` 也在程式前提過名稱，卻未教路徑基準／清單表示。
- 缺少關係：根設定的成員路徑基準、resolver 的規則版本角色、最低 Rust 版本與固定工具版本的差別、publish 布林值、`.workspace = true` 的欄位繼承形式都首次進樣本後才解釋。
- 實際影響：一個本來只需追蹤根／成員與選 package 的問題，先增加多項無法就地讀懂的設定；讀者可能把 `.workspace = true` 當 edition 自己的布林值。後文消除誤讀有效，但不符合先教再用。
- 分級：**必要／增加理解負擔，先備介紹時序**。成員／根的兩層結構本身已教清，不必把整節重做。
- 最小修正方向：在每份 TOML 前交代該段新增欄位的最低角色與讀法；或者先完成具體欄位說明再用整份設定回收。不要為此先教依賴解析完整算法或 Cargo 發布流程。
- 發現來源：本角色依正文獨立初判。未修改；修後複查未做。
