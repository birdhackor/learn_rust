## 1. 最重要的結論

Astra 支持原本的課程方向、Cargo／crate 早教、Box／dyn 順序、lifetime 分層與兩個最終專案。主要修正集中在學習關卡、真正的 API 前置、作者排程與專案驗收契約。

優先處理：

1. 建立具體的 API 使用契約與首次教學位置，包含型別、borrow／move、限制、錯誤、測試、設定與必要診斷；不要求為一次具體使用先教所有內部實作。
2. 拆開 HRTB、GAT、variance，保留全部必修，讓基本 thread／async 只等待真正需要的前置；scoped thread 的必要 HRTB 仍先教。
3. 將內容較密的單元拆成可驗收小節，較早安排 Vec、可測試的計算與資料整理等成果，逐步回收動機。
4. 平行作者依已完成的能力授權；把閱讀順序、API 必要依賴與全課完成條件分開，不依待寫章節猜測範例。
5. 在寫最終專案前定義成功、部分失敗、報告、timeout、取消與收尾，再由這些契約反推前面必須教的 API。
6. 每項進階必修都有小型完整練習與理由驗收；兩個最終專案維持自然的應用與約千行的尺度。

## 3. 排序方案的取捨

- Astra 報告第 5 節的總排序是可討論方案，不能僅因由 reviewer 提出就整張照搬。
- 將 enum／Option／Result 放到安全文字存取之前有明確收益；若文字章只使用不需要它們的 API，原順序仍可成立。
- Vec 可提早；相關 borrowing、Option、必要 trait 能力仍要先完成。
- associated type、return-position impl Trait、type alias 的最低使用知識，依真正需要位置拆出；完整深入內容仍保留。
- atomic 可接在同步經驗後；若 HTTP 測試服務以已教 Mutex 驗證並行上限，原位置亦可保留。
- HRTB／GAT／variance 的整體門檻必須拆開；其分節與各後續實際需要的關係需更新依賴表。

## 4. 兩個最終專案保留與待對齊內容

### 重複檔案搜尋器

- 保留大小篩選、串流 hash、真正內容確認、排序、文字／JSON 與部分失敗報告。
- 先定義一般檔案、symbolic link、非 Unicode 路徑與讀取失敗的處理。
- 報告中的位元組指標要有明確計算意義；依路徑計算的重複內容不等於保證能回收的實體磁碟空間。
- 對掃描時檔案變動給出完成版能提供的觀察與限制，不默認需要一致快照系統。
- 精確實體回收量、跨平台 hard link 身分與一致快照均屬可能擴大範圍的取捨；本次不加進核心需求。

### async 網址檢查器

- 固定 HTTP method、scheme、redirect、成功狀態碼及耗時範圍。
- 區分輸入錯誤、HTTP 狀態、transport failure、timeout、task panic／取消。
- 明確限制正在執行的工作；中止後不再排新工作，依策略等待或取消並確認收尾。
- 結果保留輸入身分與穩定順序，能區分完成、失敗、取消與未開始。
- 本機測試服務與所用測試 API 先教；不增加爬蟲、認證、資料庫、監控 dashboard 或多種探測策略。

### 共通的引導與答案

- 每階段由可觀察需求、輸入／結果與驗收開始；起始骨架不藏核心演算法。
- 提示逐層提供；必要操作說明仍在正文。
- 每階段有可執行完成快照；完整參考版是一份可建置、使用、測試的程式。
- 提示、測試與參考版使用同一份已教能力清單。

## 5. 保留理由與未驗證事項

- 保留數值 struct 教 move、concrete slice 先於文字、具體錯誤先於完整 Error／dyn、async 使用先於 Pin／poll 實作。
- 保留所有進階必修；以有限專題驗收，不要求每項技術都出現在最後的 CLI。
- 不把所有未列出的標準 trait 一律新增為必修小節；只有實際 API、型別、推理或診斷需要時才補。
- 保留約千行尺度；行數、可用性、學習負擔與讀者理解仍待真實實作與教材驗證。
- Astra 報告的官方來源支持具體技術疑點；不等於 51 單元的所有 API 與測試依賴已完整閉合。
- 既有專案 check.sh 通過，僅表示目前文件建置、Rust 格式、Clippy 與既有測試通過，不作為新課程或未存在專案的驗收。
